1. クラス階層
--------------------------------------------------------------------------------
1.1 Collection 階層（Seamless1 / Seamless2 共有）

    Collection<TKey, TValue,
              TSessionKey, TSessionValue,
              TReadOutput, TAddInput,
              TReadFunctions, TAddFunctions,
              TContainsFunctions, TContainsDeleteFunctions,
              TStoreFunctions, TAllocator>
        ↑
    ManagedCollection<TKey, TValue, TKeySerializer, TValueSerializer>
    UnmanagedCollection<TKey, TValue, TKeySerializer, TValueSerializer>
        ↑
    ManagedManagedCollection / ManagedUnmanagedCollection /
    UnmanagedManagedCollection / UnmanagedUnmanagedCollection
        ↑
    ManagedDictionary / UnmanagedDictionary（partial）
    ManagedHashSet / UnmanagedHashSet（partial）
    ManagedSet / UnmanagedSet（partial）

    - 静的ジェネリックパラメータで Session Functions と Allocator を
      固定し、すべてのホットパスを非仮想で解決する。
    - Managed / Unmanaged の差異は TSessionKey / TSessionValue
      （SpanByte vs 固定構造体）と Serializer の差で吸収する。

1.2 Store 階層
    CollectionStore (Seamless 共有)
        ├ ManagedCollectionStore<TKey,TValue>  (Seamless1/Seamless2 個別)
        │   ├ ManagedDictionaryStore<TKey,TValue>
        │   ├ ManagedHashSetStore<TKey>
        │   └ ManagedSetStore<TRecord,TKey>
        └ UnmanagedCollectionStore<TKey,TValue>
            ├ UnmanagedDictionaryStore<TKey,TValue>
            ├ UnmanagedHashSetStore<TKey>
            └ UnmanagedSetStore<TRecord,TKey>

    - CollectionStore は AssertIsPowerOfTwo（DEBUG）と
      GetRecoveryEntryCount を提供する基底。
    - 各 Store の Create() がコレクションインスタンスを返すファクトリ。

1.3 ファクトリ：HashStore（readonly struct）
    - 構成パラメータ（IndexSize 等）を保持。
    - Create<TKey,TValue>(ManagedTag/UnmanagedTag, ManagedTag/UnmanagedTag)
      の 4 オーバーロードを OverloadResolutionPriority で優先順位付け。
    - ストレージ用 Create<TKey,TValue>(IDevice, IDevice, ...) を別系統で持つ。
    - WithRecoveryIndexSize で Checkpoint メタデータから IndexSize を再決定。

2. Session 構成（Tsavorite ClientSession）
--------------------------------------------------------------------------------
ManagedDictionary は以下のセッションを保持する（Seamless1 例）。
    Remove_TKey_TValue_ClientSession :
        TInput=EqualityEmpty, TOutput=SpanByteAndMemory,
        TFunctions=ManagedRemove_TKey_TValue
    Remove_KeyValuePair_ClientSession :
        TInput=SpanByte, TOutput=bool,
        TFunctions=ManagedRemove_KeyValuePair
親クラス側で以下を保持する。
    Read / Add / Contains / ContainsDelete 各 ClientSession。

各 Session は以下のライフサイクル制約に従う。
    - 生成: コンストラクタおよび RecreateAdditionalSessions / Refresh で
            CreateAdditionalSessions が呼ばれる。
    - 破棄: DisposeAdditionalSessions で CompletePendingAndDispose を呼ぶ。
            Dispose(bool disposing) は disposed フラグで多重実行を抑止する。

3. 主要オペレーションの内部処理
--------------------------------------------------------------------------------
3.1 Add / Upsert
    1. TKeySerializer.Serialize / TValueSerializer.Serialize で
       ReadOnlySpan<byte> を取得。
    2. WouldOverflowMutable で容量を判定し、満杯なら ThrowLogFull / LogFull。
    3. fixed で pin し SpanByte.FromPinnedSpan を作成。
    4. BasicContext.RMW or Upsert を呼ぶ。
    5. Pending(...) で Pending を解決し、Status を確定。

3.2 Read / TryGetValue
    1. Key を Serialize、SpanByteAndMemory Output を用意。
    2. BasicContext.Read を呼び、Pending を解決。
    3. Found なら TValueSerializer.Deserialize、NotFound なら default。

3.3 Remove(TKey)
    1. ContainsDelete 系 Functions により RMW で削除を実行。
    2. Output(bool) を確認し、削除可否を返す。

3.4 Remove(TKey, out TValue)（ManagedDictionary 拡張）
    1. ManagedRemove_TKey_TValue Functions で RMW を実行。
    2. InPlaceUpdater / CopyUpdater 経路で値が SpanByteAndMemory に複製された
       場合 (Length>0)、Deserialize して返す。
    3. それ以外は default を返す。

3.5 Remove(KeyValuePair)（ManagedDictionary 拡張）
    1. Key / Value をそれぞれ Serialize。
    2. ManagedRemove_KeyValuePair Functions で RMW（Input=Value, Output=bool）。
    3. 値一致時のみ削除し、結果 bool を返す。

3.6 列挙
    - GetEnumerator() :
        InMemoryList<KeyValuePair<TKey,TValue>>（メモリ常駐分のみ）に
        KeyValueIterator が値を蓄積し、ManagedList<KeyValuePair>.Enumerator
        を返却する。
    - CreateCollection<TIterator,T> :
        ストレージ越しの全件列挙が必要な場合、ListStore.Create<T> で
        一時的な永続バッファを作り、IterateLookupAll でスキャンする。
        その後 System.Collections.Generic.List<T> にコピーして返却し、
        作業ファイルは finally で削除する（DeleteTemporaryWorkListPath）。
    - ICollection<KeyValuePair<TKey,TValue>>.GetEnumerator() :
        メモリのみで済む経路では ReadMemoryClientSession を用いる。

3.7 容量判定（OverflowMutableStrategy）
    - Memory  : (tailAddress - beginAddress) > limit - required で判定。
                limit = logMemorySize * mutableFraction（0 以下なら logMemorySize）。
    - Storage : tailAddress > limitBytes - required で判定。
                limitBytes = min(storageCapacity * limitFraction,
                                 storageCapacity - reserveBytes)。

3.8 Log Compaction
    ManagedCollectionStore.CompactLog(compactUntil) は
    Store.Log.Compact<...>(ManagedAdd.Create(), compactUntil,
                           CompactionType.Lookup) を呼ぶ。

4. シリアライズ
--------------------------------------------------------------------------------
4.1 ManagedSerializer<T>
    - MemoryPack 等を用いて可変長 ReadOnlySpan<byte> を返す。
4.2 UnmanagedSerializer<T> (T : unmanaged)
    - sizeof(T) のバイト列にメモリコピーする。
4.3 EqualityEmpty
    - 0 バイト相当のプレースホルダ値型。HashSet の Value、TInput / TContext
      に用いる。

5. SessionFunctions
--------------------------------------------------------------------------------
5.1 ManagedAdd / UnmanagedAdd : RMW で TryAdd を実装。
5.2 ManagedRead / UnmanagedRead : Read で値を Output(SpanByteAndMemory) に
                                   コピー。
5.3 ManagedContains / UnmanagedContains : 存在判定のみ。
5.4 ManagedContainsDelete / UnmanagedContainsDelete : 存在時に Tombstone を
                                                       立てて削除。
5.5 ManagedRemove_TKey_TValue : 値を Output に複製しつつ削除。
5.6 ManagedRemove_KeyValuePair / Unmanaged 版 : Value 一致時のみ削除。
5.7 ManagedIntersectWith / SymmetricExceptWith / ExceptWith / Unmanaged 版 :
    集合演算用 RMW Functions。

6. ManagedList
--------------------------------------------------------------------------------
6.1 ファイル構成
    - data file       : 任意長レコードを連続配置。
    - <path>.index    : 各レコードの先頭オフセット（long）を Capacity 個分。
6.2 メモリマップド
    - dataMappedFile / indexMappedFile を双方 MemoryMappedViewAccessor で
      開く。
    - TempListTuning に従い FileAccess / FileOptions を切り替え可能。
6.3 操作
    - Add(T) : Serialize → AppendRecord（容量を超えたら拡張）。
    - DuplicateRemoval : SortBySerializedBits でバイト列ソートし、
                         隣接重複を除去。
6.4 ライフサイクル
    - 既存ファイルがある場合は LoadState で復元。
    - data / index が片側のみ存在 → InvalidDataException。

7. Recovery
--------------------------------------------------------------------------------
7.1 ManagedDictionaryStore / UnmanagedDictionaryStore は
    GetRecoveryEntryCount() を override し、Create() で開いた一時的な
    Dictionary から GetLongCount() を返す。
7.2 HashStore.WithRecoveryIndexSize は Checkpoint メタデータから
    GetIndexSizeForCapacity に基づき適切な IndexSize（2 の冪）を選択する。

8. ライフサイクル
--------------------------------------------------------------------------------
8.1 Dispose
    - Dictionary 系: 自身の追加 Session を Dispose した後、base.Dispose を呼ぶ。
    - HashSet 系   : IntersectWith / SymmetricExceptWith Session を Dispose し、
                     base.Dispose を呼ぶ。
    - ownedStore がある場合（CreateOwned 経由）は Store も同時に Dispose。
8.2 IsDisposed
    - 各 Collection 内部の disposed フラグを返す。
    - 多重 Dispose は no-op。

9. スレッディング
--------------------------------------------------------------------------------
9.1 Session は単一スレッドからの利用を前提とする。
9.2 集合演算など複数 Session を併用する処理では、各 Session のロック粒度を
    Tsavorite に委譲する。
9.3 GC は ServerGarbageCollection=true（プロジェクト設定）。

10. テスト構成
--------------------------------------------------------------------------------
10.1 Test.Seamless1, Test.Seamless2 はそれぞれ Seamless1.dll / Seamless2.dll を
     参照し、同一の xUnit テストコードを共有する。
10.2 テストクラス名はテスト対象クラスと同一とし、メソッド順序も一致させる。
10.3 1 メソッドの中で複数ケースを {} スコープで区切り、コメントで意図を明示する。
10.4 Tsavorite バージョンによる差分は #if で分けず、両プロジェクトに対応する
     コードを別々に置くことで吸収する。

11. ビルド構成
--------------------------------------------------------------------------------
11.1 共通 SDK / TFM は Directory.Build.props と global.json で管理する。
11.2 Seamless1 : DefineConstants TSAVORITE1_1_1, Microsoft.Garnet 1.*。
11.3 Seamless2 : DefineConstants TSAVORITE2_0BETA3, Microsoft.Garnet 2.0.0-beta.3。
11.4 共有プロジェクト Seamless.projitems を Import で共有する。
11.5 AllowUnsafeBlocks = True（fixed / SpanByte.FromPinnedSpan 用途）。

12. コーディング規約適用
--------------------------------------------------------------------------------
- インデントはスペース。
- 識別子・記号間スペース無し、波括弧同一行。
- if-else は片方が空でも { } を省略しない。
- 三項演算子はカバレッジ計測の都合で if-else を優先。
- Managed/Unmanaged および 1.1.1/2.0beta3 の対応ファイルは行番号レベルで
  揃え、片側だけメンバー順や空行配置を変更しない。

13. 既知の制約・注意事項
--------------------------------------------------------------------------------
13.1 Iterator 内部で List<T> 等のオンメモリコレクションに全件を蓄積しては
     ならない。チャンク（Const.Chunk_Length）または ListStore による永続バッファ
     を介する。
13.2 1.1.1 と 2.0beta3 の SessionFunctions シグネチャ差は SessionFunctions 階層に
     閉じ込め、上位 Collection API のシグネチャを変えない。
13.3 ManagedDictionaryStore は Unmanaged×Unmanaged の組合せを生成しない
     （InvalidOperationException）。Unmanaged×Unmanaged は
     UnmanagedDictionaryStore で生成する。
