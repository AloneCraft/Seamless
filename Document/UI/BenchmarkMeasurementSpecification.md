# ベンチマーク計測仕様

## LoopCount校正

- 指定する測定時間は、1回あたりの表示時間ではなく、最終1バッチの合計実測時間である。
- LoopCountは比較行ごとに管理し、右列だけを校正対象とする。
- 右列が指定時間未満なら継続完了を表示してLoopCountを2倍にし、右列だけを再測定する。
- 右列が指定時間以上になったLoopCountを比較行の最終LoopCountとする。
- 左列（3列比較では左列に続けて中央列）は最終LoopCountで一度だけ測定する。左列・中央列の合計時間が指定時間未満でも、成功なら完全完了である。
- 全列の最終LoopCountは同一でなければならない。失敗・例外・タイムアウトは完全完了に含めない。
- 右列が`int.MaxValue`でも指定時間未満なら、理由付き失敗にする。

## 表示と集計

- SourceTabの行所属は、タブ定義のプロジェクト名、アセンブリ名、型プレフィックスがすべて一致するBenchmarkケースだけを対象とする。
- 型列は反射カタログが確定した最も近いジェネリック親クラスの型引数を表示し、`System.Int32`は`int`、`System.String`は`string`として整形する。複数の型引数はカンマ区切りとし、表示用型が空のケースはDBへ保存しない。
- 同じ表示用プロジェクト名を複数タブで共有していても、別アセンブリまたは別タブのケースで欠落側を補完してはならない。SourceTabを一意に解決できない入力は即時エラーとし、先頭候補、選択中タブ、System.Arrayへのフォールバックは禁止する。
- 正規タブ・正規アセンブリ内で片側にしか存在しないBenchmarkケースは片側行として表示し、存在しない側の日時セルには時計アイコンを表示せず`対象なし`と表示する。
- 時間セルは1回あたり時間を表示し、ツールチップで最終バッチ合計時間とLoopCountを表示する。
- CPU列の右側の`ループ回数`列は、右列・中央列・左列の順で最初に値を持つ列のLoopCountを単一の数値で表示する（左右不一致時のペア表示はしない）。いずれの列にも値がなければ空欄とし、ソートでは欠測として末尾へ送る。
- 比較表は通常Runを`Left:Right`、Scalable Runを`Current:Previous`の順で扱う。時間・メモリとも`左値/(左値+右値)`と`右値/(左値+右値)`をシェアとする。
- 両側が0の場合は`0.00:0.00`、片側が0の場合は`0.00:1.00`または`1.00:0.00`、欠測・負数・非有限値は`-`と表示する。
- 通常値は2桁表示の合計が1になるよう右側を補数表示する。ソートには丸め前のLeftシェアを使う。
- 時間シェア列とメモリシェア列は、丸め前のLeft／Currentシェアを青`#2563EB`、Right／Previousシェアをオレンジ`#F97316`で横幅表示する。表示文字列、時間回帰の`⚠`、ツールチップ、列順、ソート値は従来どおり維持する。両側0と欠測では色を表示しない。
- 上部の時間シェア・メモリシェアは、選択中Runで実測済みの左右成功ペアのLeftシェアを算術平均し、`Left:Right`で表示する。引継ぎ表示値や現在のチェック状態は集計対象にしない。
- 時間の勝敗色はLeft/Right比較に従来の±5%許容を維持する。改善候補はLeft負荷がRightより厳密に大きい行を対象とする。
- 改善プロンプトは候補Grid、候補チェック、時間／メモリ切替、上位件数制限を持たない。時間またはメモリでLeft負荷がRightより厳密に大きい候補を重複なしですべて本文へ自動反映し、本文編集とコピー操作だけを提供する。
- 改善プロンプトは、Benchmark実行や特定の型・引数・N・データ内容だけを検出する一般化不能な特殊化を禁止する。正しさ、列挙順、遅延実行、例外、破棄、副作用、公開API互換性を維持し、複数サイズ・異なるデータ分布・境界条件での回帰テスト、時間とメモリの同時評価、反復測定による再現確認を要求する。
- ソート候補は表の列順とし、型、ベンチマーク、CPU、ループ回数、引数、Left日時・時間・メモリ、時間シェア、メモリシェア、Right日時・時間・メモリの順に並べる。日時の初回クリックは古い順で、欠測は昇降順とも末尾に置く。
- 完了時は時間シェア降順へ自動変更し、`Seamless.SortRules.v2`へ保存する。旧v1設定は読み込まない。
- 集計対象がない場合はシェアを`-`と表示する。

## 履歴とDB契約

- 基準性能比チャート、基準／履歴の外側タブ、積み上げ系列、チャートクリックによるGrid選択は提供しない。右側にはフォーカス行の履歴性能比を直接表示する。
- 履歴チャートは通常版でLeft/Right、Scalable版でCurrent/Previousの2系列、Y軸0～1で表示する。時間／メモリの内部切替だけを残し、表示中の指標だけを遅延生成する。初回は2系列、両指標を一度ずつ表示した後も合計4系列を上限とし、手動更新ボタンは持たない。
- 初期フォーカス行は現在の表示順で左右計測済みの先頭行とする。DB読込、計測完了、フォーカス行変更で表示中の履歴を自動更新し、非表示指標は次回表示まで更新を保留する。一度生成したChartはアプリ終了まで保持する。
- 通常版の履歴識別子はタブ・型・ベンチマーク、Scalable版はこれらに全引数軸を加える。SQLで識別子を完全一致させ、1行・1指標につき新しい順で最大1000点を取得後に時系列順へ戻す。全タブ取得後の絞り込み、別行・別タブ・欠落引数によるフォールバックは禁止する。
- 通常DBは未使用の分析ビューを作成しない。
- Scalable DBの正規ビューは`Scalable履歴`と`Scalable前回シェア`で、シェア列は`今回時間シェア`、`前回時間シェア`、`今回メモリシェア`、`前回メモリシェア`である。
- 通常DBのスキーマ版は24、Scalable DBは20。既存計測行は変更せず、旧比率ビューや基準シェアビューとの互換契約は持たない。版不一致は自動移行・自動削除せず、アプリ終了確認と明示バックアップ後の直接更新を要求する。
- 通常DBは単一の`ベンチマーク`表を持たず、`実行`表とタブ別の11表（`書き換え`、`パイプライン融合`、`述語プッシュダウン`、`Array`、`IEnumerable`、`Range`、`List`、`Persisted(Seamless)`、`Persisted(System)`、`Tsavorite(Seamless)`、`Tsavorite(System)`）で構成する。各タブ表の計測列はタブ定義の列見出しから導出し、識別情報（アセンブリ名・型完全名）は側ごとに独立した列で保持する。

## 回帰履歴

以前は左右とも指定時間へ到達することを完全完了条件にしていた。また、表の1回あたり時間を見て最終バッチ時間と混同しやすく、`Any`がLoopCount 524288でFLinq 34.8ms、ZLinq 43.2msの表示でも処理が完了する問題があった。その後、左列のみで校正する方式に変更し、最終バッチ合計時間と共有LoopCountを明示表示するようにした。現在は右列を校正対象とし、決定したLoopCountで左列・中央列を測定する。
