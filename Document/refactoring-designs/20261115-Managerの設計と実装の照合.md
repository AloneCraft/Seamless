## 2. 統一仕様（11/14）と Manager の食い違い

統一仕様の「影響範囲」は `Seamless.Management*`（設計器、目録）を挙げているが、手順A〜K に Manager の作業が書かれていない。調べた結果、次の作業が要る。

| 項目 | 統一仕様 | Manager の今のコード（事実・推測） | 影響 | 次にやることの案 |
|---|---|---|---|---|
| M1 表の作成 | 表は `<root>.Tables`（スキーマ別は `<root>.Tables.<スキーマ>`）の型に `[Key]` を付ける。旧方式（`Keys` と `Records` の二重書き、コンテナの表のプロパティの手書き）は削除（手順B） | 新しい表を旧方式で書き出す：`<root>.Keys.<名前>` と `<root>.Records.<名前>` の2つの型と、コンテナへ `public Table<キー,行> X=>this.Table<…>(row=>new(…));` を足す（`Seamless.Management/DatabaseDesigner.cs` 97〜105行） | 手順B の完了の条件4（`<root>.Records` を宣言するファイルが無い）を Manager が破る。B の後は Manager で作った表がビルドできない | 新方式で書き出す。列は平らな基本の型だけ受け付ける |
