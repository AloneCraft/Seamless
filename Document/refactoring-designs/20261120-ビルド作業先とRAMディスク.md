# ビルド作業先とRAMディスク

## 合意と現状

利用者は、`source-builds` とSDKの作業先を一つの設定で指定し、WindowsのWinFsp MEMFS、Linuxのtmpfs、macOSのRAMディスクで使えるようにする方針を承認した。現行は管理ルートの直下に `source-builds` と `sdk-drafts` を置く。

## 配置

起動前に環境変数 `SEAMLESS_BUILD_WORK_ROOT` に、サーバープロセスから見える準備済みディレクトリの絶対パスを設定する。管理ルートごとに作業サブディレクトリを作り、その配下に `source-builds` と `sdk-drafts` を置く。未設定時は現行配置を使う。設定先が利用できない場合は起動時に理由とパスを表示する。

管理領域の永続ルートは従来どおりで、下書き、削除予定、公開世代、DBデータを保存する。確認時のDLLは一時領域に置き、適用時は永続側の公開準備領域に必要なファイルを書き、永続側で公開先へ改名する。RAMディスクの作成・マウントと容量の設定はOSで行う。

確認用成果物の回収と、SDK作業領域の所有プロセスを確認した回収を維持する。設定切り替え時は永続ルートの従来の `source-builds` も回収する。異なる管理ルートが同じ作業先を使っても互いの作業へ影響しない。

## 運用

| OS | ホスト側で準備する領域 | 環境変数の値の例 |
|---|---|---|
| Windows | WinFspの開発者ファイルを含めて導入し、MEMFSをマウント | `R:\SeamlessBuild` |
| Linux | サービスの利用者が書き込める容量制限付きのtmpfs | `/run/seamless-build` |
| macOS | RAMディスク上のサービス用ディレクトリ | `/Volumes/SeamlessRAM/build` |

環境変数はManagerまたはサーバーを起動するプロセスに設定する。ディレクトリを先に用意し、サービスの実行アカウントがアクセスできることを確認する。NuGetを参照するクライアントや、通常ディスクでビルドする開発・本番ホストは追加のドライバーなしで利用できる。WinFspの導入は、MEMFSを使用するWindowsホストのOS管理者が行う。

WinFspを使わない場合は環境変数を未設定のまま起動する。管理ルート直下の `source-builds` を適用・取消や次回起動時に回収し、SDK作業を回収した後の `sdk-drafts` が空であればフォルダーごと削除する。

## 検証

Windowsでは管理ルートとビルド作業先を分け、変更確認中のDLLとSDKの一時フォルダー、適用後の公開ソース・DLL、再起動後の下書きと公開DBを照合する。WinFspではMEMFSのマウントを実際に使う。Linux・macOSの実機結果は確認できた範囲を記録する。
