# Optimization Rules & Transformations

## 1. Multi-Scope Loop-Invariant Hoisting
- Scan all lambdas (`Select`, `SelectMany`, `Where`, `Join`, `GroupJoin`) for expressions, method calls, or properties that do not depend on the lambda's input parameters.
- **Hierarchical Lifting:** - If an expression depends on NO lambda parameters, hoist it completely outside the entire query.
  - If an expression depends on an outer lambda parameter (e.g., `a`) but NOT the current inner lambda parameter (e.g., `b`), hoist it into the intermediate scope (the body of the outer lambda) so it evaluates exactly once per inner sequence generation.

## 2. SelectMany Structural Transformations & Fusion
- Convert nested `SelectMany` structures into flat method chains using transparent identifiers or explicit projection blocks.
- **Predicate Pushdown:** If a `Where` clause exists after a `SelectMany` or on the merged sequence, push down the `Where` filter *into* the inner sequence *before* flattening occurs. This reduces the Cartesian product size from $O(N \times M)$ to $O(N \times K)$.

## 3. Join / GroupJoin Optimizations
- **Key-Selector Hoisting:** Hoist any part of `outerKeySelector` or `innerKeySelector` that contains computations independent of the element (e.g., static method calls) out of the matching engine.
- **Hash-Join Decomposition:** Transform standard LINQ `Join` or `GroupJoin` into an explicit pre-calculated hash lookup strategy if the inner source is evaluated multiple times or can be materialized into an optimized `Dictionary<TKey, TValue>` or custom lookup outside the main loop.
