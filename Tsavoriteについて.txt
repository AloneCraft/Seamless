重要な誤解があります。両方ともMemoryPackを使っています。Collections の Collection5.csにもSerialize<T>()` = MemoryPack があることを先ほど確認しました。
本質的な違いは「シリアライザを使うかどうか」ではなく、シリアライズ済みバイト列を何の型で Tsavorite に渡すかです
【Collections — ObjectAllocator】
ManagedClass
  → MemoryPack → byte[]
    → FixedSpanByteKey / PinnedSpanByte  ← IHeapObject（マネージドヒープ上のラッパー）
      → ObjectAllocator がポインタとしてログに保持
        → ディスク退避時に IObjectSerializer<T> で再シリアライズ

【Collections11 — SpanByteAllocator】
ManagedClass
  → MemoryPack → byte[]
    → SpanByte  ← blittable（ポインタ＋長さの値型）
      → SpanByteAllocator がメインログにインライン格納
        → ディスク退避時も追加変換なし（バイト列のままコピー）
	ObjectAllocator	SpanByteAllocator
Tsavoriteに渡す型	IHeapObject（managed ref）	SpanByte（blittable）
GC追跡	必要（managed参照をログが保持）	不要
Object Log	あり	なし
IObjectSerializer<T>	ディスク退避時に呼ばれる	呼ばれない
MemoryPackの使用	両者ともアプリ層で使う	← 同じ
つまり：
•	ObjectAllocator ≠ シリアライザの役割。MemoryPack は両方で使う。
•	ObjectAllocator はマネージドポインタの管理者。FixedSpanByteKey/PinnedSpanByte というマネージドラッパーをログに持ち、GC対象になる。ディスクへ退避する際に「再度」IObjectSerializer<T> を呼ぶ（= 2段階シリアライズ）。
•	SpanByteAllocator はバイト列の直接格納。MemoryPack で変換した byte[] を SpanByte（値型）にして渡すだけなので、GCもObject Logも追加シリアライズも不要。
仕組みの整理
Collections11（SpanByteAllocator）
// HashSet.Add() — 書き込みの全経路
var keyBytes = Serialize(item);          // ← MemoryPack: T → byte[] ここで完結
fixed(byte* pKey = keyBytes) {
    var key = SpanByte.FromPinnedPointer(pKey, keyBytes.Length);
    Session.BasicContext.RMW(ref key, ...);   // Tsavoriteに渡るのはbyte列のみ
}
SpanByte は blittable struct なので Tsavoriteログ内にマネージド参照は一切存在しない。
Mutable / ReadOnly / ディスク —— どの領域でも常に「シリアライズ済みバイト列」として格納される。
MemoryPackObjectSerializer は型として存在するが 呼ばれる経路がない（KeySerializeCreator()/ValueSerializeCreator() が null を返す）。
Collections（ObjectAllocator）— 比較
// Collection`5.cs PrivateTryAdd()
var ValueBytes = Serialize(Value);                        // MemoryPackでbyte[]化
var Input = PinnedSpanByte.FromPinnedSpan(ValueBytes);   // マネージドクラスに包む
Session.BasicContext.RMW(FixedKey, ref Input, ...);      // Tsavoriteにはrefを格納
// IObjectSerializer が呼ばれるのはページがディスクに退避される時だけ
Collections11 (SpanByte)    Collections (ObjectAllocator)
Mutable領域の内容           シリアライズ済みバイト列    PinnedSpanByte/FixedSpanByteKey のマネージド参照
IObjectSerializer 呼び出し  なし（dead code）           ディスク退避時のみ
書き込みコスト              毎回MemoryPack実行          毎回MemoryPack実行＋マネージドオブジェクト生成
GC負荷                      なし                        レコード数に比例
