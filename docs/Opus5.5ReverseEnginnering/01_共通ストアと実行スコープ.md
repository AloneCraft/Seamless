# 01 共通ストアと実行スコープ（Seamless.Execution）

|---|---|---|---|

## 1. 不変条件

1. **永続ストアは `Save()` した時点だけが確定する。** 破棄では保存しない（`Store.cs:208` のコメントと実装 `209-240`）。【記録】決定5（2026-09-19 ユーザー確定）。
2. **同じ永続フォルダを二重に開けない。** 開いている間は `store.lock` を排他で持つ（`Store.cs:54-65`）。
3. **一時ストアは破棄でフォルダごと消える**（`Store.cs:229-235`）。
4. **メモリストアは保存できず、フォルダを持たない。** `Save()` は `NotSupportedException`、`GetComponentDirectory` は `InvalidOperationException`（`Store.cs:94-96`、`158-160`）。
5. **子資源の名前はストア内で一意で、ファイル名として安全な文字だけ。** `.`、`..`、区切り文字、使えない文字を拒否する（`Store.cs:111-115`、`241-246`）。
6. **保存の記録（`store.json`）は一時ファイルへ書いてから置き換える**（`Store.cs:258-263`）。書き込みに失敗したら、保存番号の一覧を元に戻す（`Store.cs:167-172`）。
7. **予算は上限を超える予約を拒否し、二重解放を検出する**（`ResourceBudget.cs:54-56`）。例外は種類（`Memory`/`TemporaryStorage`/`SingleElement`）・要求量・上限を持つ（`ExecutionOptions.cs:93-98`）。
8. **1スコープで同時に2つの列挙を走らせない。** 別スレッドからの入場は例外（`ExecutionScope.cs:27`、`34`）。
9. **Codec の登録内容は最初の解決の後は変わらない**（`CodecRegistry.cs:14`、`21`）。
10. **回収は「形式が正しく、ID が名前と一致し、所有ロックを取れた」フォルダだけ。** 壊れた・所有確認できないフォルダは消さない。リパースポイントは辿らない（`TemporaryResourceRecovery.cs:17-33`）。
11. 既定の上限はメモリ 256 MiB・ディスク 16 GiB（`StoreOptions.cs:13-14`、`ExecutionOptions.cs:88-89`）。これはプロセス全体の上限ではなく、管理対象の予約の上限である（`docs/execution-and-database.md`）。

## 2. 禁止事項

- ストアに Garnet/Tsavorite の型を持ち込まない。ストアはエンジンを知らない（【記録】決定4）。
- 破棄時に暗黙の保存をしない（決定5に反する）。
- 保存の記録を直接上書きしない（途中で落ちると記録が壊れる）。
- 回収処理で、所有を確認できないフォルダを削除しない。
- ページ・セグメント・索引などエンジンの詳細設定を、共通ストアの公開 API に出さない（【記録】決定3・決定6。詳細は `internal` でテストとベンチからだけ使う）。

## 3. 前提条件

- エンジン側は `IStoreComponent`（名前、`Save()` が返す状態文字列、`Load(state)`、`Dispose()`）を実装してストアへ登録する（`StoreOptions.cs:21-25`）。
- エンジン側は登録前に `TryGetSavedState` で前回の状態を読み、索引の大きさなどを決めてよい（`Store.cs:142-153`）。
- 子資源は自分が破棄されるときに `Unregister` を呼ぶ（`Store.cs:128-137`）。
- 一時ストアの既定フォルダは `%TEMP%/Seamless/Store`、実行スコープは `%TEMP%/Seamless/Execution`（`Store.cs:35`、`ExecutionOptions.cs:90`）。

## 4. 変更範囲 / スコープ

- `Seamless.Execution/*.cs` と `Execution.Tests/*`。
- 共通ストアの形を変える場合は、登録口を使う `Seamless.Collections.Tsavorite/Stores/StoreExtensions.cs`、`TsavoriteLayout.cs`、`Seamless.Collections.Persisted/StoreExtensions.cs` を同時に合わせる。

## 5. 非対象 / Out of Scope

- エンジン固有の保存形式（Tsavorite のチェックポイント、Persisted のファイル形式）。状態文字列の中身はエンジンが決める（`StoreOptions.cs:19`）。
- プロセス全体のメモリ制限（検証基盤がピーク private bytes を別に記録する）。
- OS 停止や電源断に対する耐久性。【記録】強制終了（プロセス kill）では保存時点へ戻ることを 5/5 回確認済み（EXP-0005）。OS 停止・電源断は未検証。

## 6. 完了条件 / 成功条件

- 3種類のストアが上の不変条件1〜6を満たす。
- Tsavorite と Persisted の両方を同じストアに作れて、上限を共有できる。
- リポジトリ内の利用側（DB、LINQ、テスト、ベンチ）が共通ストア経由で資源を得ている（**未達**：段階5）。

## 8. 移行条件

- 旧来の「利用者がデバイスとチェックポイント用フォルダを用意する」方式から、「ストアから作る」方式へ移る。
- 利用側は、プロジェクト群ごとに共通ストア経由へ置き換え、各区切りでビルドと回帰テストを通す。順序は DB → LINQ → テスト・ベンチ（【記録】`Work/qa/handoff.md`）。
- 旧形式の保存データは変換しない。

## 9. ロールバック条件

- 共通ストアの変更でエンジン側の保存・復元テストが落ちたら、共通ストアの変更を戻す（エンジン側は登録口にしか依存しないので、戻す範囲は `Seamless.Execution` に閉じる）。
- 基準は `73950c6e`（共通ストアの土台を入れたコミット）。

## 10. 既知の問題 / 許容事項

- 共通ストアの保存は、各子資源の `Save()` を順に呼んでから記録を書く。途中の子資源で失敗した場合、それより前の子資源はエンジン側で保存済みのまま記録には残らない（`Store.cs:161-165`）。【推測・中】次回開いたときは直前の保存番号の状態へ戻るため害は小さいが、ディスク上に不要な保存物が残る可能性がある。
- 保存番号は増える一方で、古い保存番号を消す機能はない（`Store.cs:166`）。【推測・中】長期運用では `store.json` と各エンジンのチェックポイントが増え続ける。
- 一時ストア自体は起動時に残骸回収を行わない。回収は `TemporaryResourceRecovery.RecoverAbandoned` を明示的に呼んだときだけ（呼んでいるのは `Seamless.Database/DatabaseContainer.cs:36` とテスト）。
