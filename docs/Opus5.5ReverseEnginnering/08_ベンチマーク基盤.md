# 08 ベンチマーク基盤

## 行うべき機能

FLinq と比較対象（ZLinq、`System.Linq`、最適化を1つ無効にした FLinq）を、同じ条件・同じ論理 CPU で測り、結果を SQLite に残して比べられるようにする。

| 機能 | 内容 | 状態 | 根拠 |
|---|---|---|---|
| 通常 Benchmark UI | ソース別・最適化別のタブで、左右2系列を比較表示 | 実装済み | `Shared/UI.Core/BenchmarkSourceTabs.cs:158-204` |
| 最適化の効果比較タブ | 書き換え・パイプライン融合・述語プッシュダウン・射影融合を「全最適化」と「1つ無効」で比較 | 実装済み | `BenchmarkSourceTabs.cs:159-162` |

| Scalable UI | 件数を増やしたコレクション測定、前回との比較 | 実装済み | `BenchmarkSourceTabs.cs:105-147`、`Benchmark/Benchmark.Scalable.*` |

## 1. 不変条件

1. **比べるのは同じ条件の結果だけ。** 左右は同じ論理 CPU・同じループ回数で測る（`Document/UI/BenchmarkMeasurementSpecification.md`「測定順序」）。
2. **ループ回数系の行は、左列（FLinq）で回数を確定し、右列はその回数で1回だけ測る。** 右列の時間を理由に回数を倍にしない（同上）。
3. **完全完了の条件を緩めない。** 測定値があるだけ、進捗が終わっただけ、左列が指定時間に届いていないだけの状態を完了にしない（同上「完全完了の必要条件」）。
4. **動的に増やしたループ回数は行の中に閉じ、他の行へ持ち越さない**（同上「状態管理と再開」、2026-07-10 の回帰）。
5. **UI の DB は自動移行しない。** 旧スキーマは互換表示・復元せず、明示エラーにする。スキーマを変えるときは、バックアップを取ってから対象 DB を直接作り直す（`Database.md`「UI SQLite」、`AGENTS.md`）。
6. **SQLite は WAL・busy_timeout 30 秒・外部キー有効で開く**（`Shared/UI.Storage/UiRunStore.cs:429`）。書き込みは直列キューで行い、UI スレッドを止めない（`UI.md`「完了」）。
7. **Stop→Run は全消去してから測り直す。Pause→Run は未計測のチェック分だけを測る**（【記録】ベンチ運用メモ、コミット `d4a9bce1`、回帰テストあり）。
8. **緑の選択状態はタブごとに保つ。タブを切り替えても消さない**（【記録】ベンチ運用メモ）。
9. **履歴の一括消去は「DB 保存」を確定したものだけが対象。未保存の下書きは残す**（【記録】ベンチ運用メモ）。
10. **校正値は本測定として保存しない**（`docs/verification.md`「検証スイート」）。

## 2. 禁止事項

- 起動時処理・スキーマ版の増加で UI DB を自動削除・自動移行しない。
- 自作の簡易計測で「測定の不具合だ」と結論しない。判断は Worker の実測で行う。
- ウォームアップの監視に `EventListener` を使わない（昇格そのものを止めてしまう：【記録】ベンチ運用メモ「計測が最適化前のまま二極化」）。
- 固定の Left/Center/Right 列を DB に持たせない。タブの Grid 見出しを接頭辞にした明示列で保存する（`Database.md`）。
- VS から実行したときに古い Worker が使われる状態を放置しない（BUG-0009 の確認待ち）。

## 3. 前提条件

- Windows、MAUI（`net10.0-windows`）、Syncfusion の DataGrid/TabView。
- BenchmarkDotNet（`InProcessEmitToolchain`）と独自の較正ループ。
- 比較対象の ZLinq 1.5.6（`Benchmark.Dynamic実装計画.md` §2）。
- UI 自動操作は Appium/UIA。Grid・SfDataGrid・SfTabView は AutomationId が見えない制約がある（【記録】ベンチ運用メモ「UIA/Appium テスト制約」）。

## 6. 完了条件 / 成功条件

- 全タブで、選択した行が「完全完了」の条件で測られ、DB に保存され、再起動後に同じ表示へ復元できる。
- 比較の数字が、同条件の再測定でばらつきの範囲に収まる（【記録】1行の再測定ノイズは ±21% 程度あり、比率だけで行を選ばない）。
- UI 自動操作テストが、開始・タブ切替・履歴復元・CPU 列ソート・比較表示・終了確認を網羅する（未達）。

## 8. 移行条件

- スキーマを変える場合：対象 DB のバックアップ → 本体・WAL・SHM の明示破棄 → 新スキーマで作成（旧履歴は移さない）。
- 計測方式を変える場合：過去の実行 ID との比較可能性が失われるので、変更前にユーザーの承認を得て、変更後に全タブを新しい実行 ID で測り直す（【記録】ベンチ運用メモ）。

## 9. ロールバック条件

- 完全完了の判定、保存・復元、CPU 割当のいずれかで回帰が出たら、その変更を戻す。DB はバックアップから戻す。
- 計測方式の変更で、同条件の再測定の結果が大きく変わり説明できなければ、計測方式を戻す。

## 10. 既知の問題 / 許容事項

- 【記録】BUG-0009（NEEDS_HUMAN）：VS で Benchmark.UI を実行すると、最新の Worker・DLL で動かないことがある（ターミナルのビルドでは最新）。`a8f419f1` で対策済み、VS での確認待ち（Q-006）。
- 【記録】BUG-0011：`Test/Benchmark/BenchmarkWorkerBuildContract.cs` が、BUG-0009 の修正（a8f419f1）で廃止した `CopyBenchmarkWorkerHost` ターゲットを探して失敗する。テストの更新漏れ。
- `.NET 12` 以降を対象にすると、`BenchmarkWorkerRuntime.cs:10-11` の `#error` でビルドが止まる。意図的な確認ポイント（dotnet/runtime#129020 の採否を確かめて、ウォームアップ判定を公式 API へ置き換える）。
- 【記録】ベンチの既知失敗：`Sum` の overflow、`TryGetNonEnumeratedCount`。
- `Database.md` は通常 UI のスキーマ版を 24・表を9個と書いているが、実装は版 26（`UiRunStore.cs:6`）で、射影融合タブ（`BenchmarkSourceTabs.cs:162`）がある。`UI.md` の測定仕様は版 16 の記述を含む。
