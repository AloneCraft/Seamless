# DB定義のC#プロジェクト連携

## 保存と未適用の区別

編集する正本は通常の`Schema.csproj`に含まれる`.cs`ファイルです。VS Codeでファイルを保存しても、稼働DBへ適用するまではオブジェクトタブに`*Sales.Customers`のように表示します。`*`は稼働版との差分を表し、IDEの未保存バッファを意味しません。

Managerはファイル保存と個人下書きの保存を行います。ファイルの変更検出・下書き保存・IDEのビルドは、DBの移行や公開を実行しません。稼働版への反映には従来の「変更を検証」「変更を適用」を使います。

## 開発環境での操作

1. Managerで通常DBを作成します。Seamlessリポジトリが見つかる開発環境では、DBごとのC#プロジェクトをManagerの設定領域の`Sources`配下へ生成します。保存先を指定する場合は環境変数`SEAMLESS_SOURCE_WORKSPACE_ROOT`を起動前に設定します。
2. 既存DBは下書きを開き、「C#プロジェクト…」から空の保存先へ書き出します。連携済みの場合は、この操作でプロジェクトのパスを表示します。
3. 生成したフォルダーをVS Codeで開きます。`.vscode/tasks.json`の既定ビルドは`dotnet build Schema.csproj`です。C# 14対応の.NET 10 SDKが必要です。サーバー本体のプロジェクトは書き換えません。
4. GUIで作った表・スキーマのファイルは同じプロジェクトへ追加します。VS Codeで保存した変更は、Managerが起動中は約1秒間隔で確認します。対象のタブを背景で追加・更新し、稼働版へ未適用なら`*`を付けます。現在の画面・選択は切り替えません。

プロジェクトは指定したSeamlessリポジトリのランタイムとソース生成器を参照します。リポジトリを自動検出できない場合は`SEAMLESS_SOURCE_REPOSITORY`を設定します。現段階では、配布ZIPだけから必要な開発用参照一式を生成・配布する機能はありません。存在しないNuGetパッケージを仮定したプロジェクトは作りません。

IDEのビルド結果をそのまま稼働DBへロードする経路ではありません。適用前にはサーバー側の許可済み参照・C#検査・ビルド・移行検証を通します。ソースが同じことだけで、別の開発環境で作ったDLLの内容や参照先がサーバーの成果物と一致すると保証するものではありません。

## 復旧と競合

`.seamless/workspace.json`に稼働版、最後の同期版、作業中の下書き、下書きの版、Manager編集を取り除くための情報を保存します。これは編集用の別C#ファイルではありません。ソースには履歴上の定義を含むため、フォルダーを許可のない相手と共有しないでください。認証のパスワードやトークンは保存しません。

GUIと外部ファイルの両方に変更がある場合は、最後の同期版を基準に比較します。重ならない構文上の変更は統合し、同じ箇所や追加・削除が競合した場合は外部ファイルを上書きせず、両側を`.seamless/conflict.json`へ保持します。入力途中のC#も保持し、ビルド・適用時の検査と分けます。

書き換え前に`.seamless/pending.json`を永続化し、各ファイルと同期記録を個別に置き換えます。複数ファイルとサーバーのシステムDBを一つの原子的な書き込みとは扱いません。中断後に開き直すと、記録された変更前・変更後の内容と実ファイルが一致する場合だけ書き込みを完了します。別の保存が入っていた場合は記録とファイルを保持して停止します。サーバーへの下書き保存は基準版・下書き版を照合し、別利用者の変更を上書きしません。

## 現在の対応範囲

- 連携対象は生成済みプロジェクトに登録されたソースです。GUIでのファイル追加は追跡します。外部からの任意のファイル追加・削除、プロジェクトのCompile一覧変更は自動で推測せず確認待ちとします。
- IDEの未保存バッファは取得しません。IDEが後から保存した内容は新しい外部変更です。
- オブジェクトタブは同じC#エディターへの入口です。表の設計と表示を全面的に一体化したタブ、削除オーバーレイ、依存タブを選ぶ一括保存、稼働版へ戻す差分画面は別途実装が必要です。
- Manager由来のソース編集を取り除く基礎処理はあります。移行定義・新規宣言への外部編集など、依存を安全に分離できない取消は拒否します。GUIの取消メニュー一式が完成したという意味ではありません。
- この連携先はManagerを動かすPCのファイルです。遠隔サーバーの任意のパスへ直接書き込む機能ではありません。サーバーのシステムDBにはAPI経由で個人下書きを保存します。

自動同期の競合検査は、一般のエディターと共有するファイルシステム上の協調です。他のエディターはManagerのロックに参加しないため、外部保存と置換の完全な相互排他を保証するOS機能ではありません。同期記録、変更直前の再確認、競合時の内容保持で復旧できるようにします。
