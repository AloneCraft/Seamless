## 残っている主な群(この後の修正の対象)

1. **Range の x%C のキー**: OrderBy/ThenBy 系(140〜170倍)、DistinctBy(36倍)、MaxBy/MinBy(26倍)、CountBy(12倍)、GroupBy/ToLookup(5〜6倍)。理想版は剰余類の構造から並びとグループを直接作る。
2. **Range の Join(45倍)と SkipLast(12倍)**、押し下げタブの Range の Order/Distinct/Reverse の後の Where(5〜25倍。Range に対しては何もしない段)。
3. **参照型(ClassInt32)の複合連鎖**: 押し下げ・射影融合タブの ClassInt32 行が Int32 行より大きく遅い(押し下げ 1.93 対 1.22、射影融合 2.74 対 2.07)。差し替えメソッドから入れ子のジェネリック構造体の TryGetNext を回す形は、参照型の共有ジェネリックコードで内側がインライン化されない(`Work/exp/nestedconsume`: 入れ子 14.8µs、直接ループ 4.3µs、int はどちらも約4µs)。
4. **射影融合の SelectMany(x => Enumerable.Repeat(x,1), …)**: 5〜19倍。要素ごとに1つだけを流すので Select と同じ。
5. **OrderBy(x => x)(Array/List/IEnumerable の Int32)**: 2.6〜3倍。Order() と同じなのに、キーを計算する並べ替えの経路を通る。
6. **IEnumerable タブ**: SkipLast/TakeLast・Reverse・Append・Zip・Select_indexSelector の ClassInt32 で 2〜3倍。
7. **Empty(6行)**: 理想版がベンチの枠である反復のループごと省いていた(FLinq は枠の文を書き換えない)。理想版の不備として直す。
