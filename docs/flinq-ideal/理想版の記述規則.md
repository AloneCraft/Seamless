# 理想版の記述規則

手書きの理想ループ版(`Benchmark.System.Linq.Enumerable.*.Ideal` など)は、FLinq の出力が理論上最良かを測る物差しである。次の規則で書く。

## 目的と位置づけ

- 演算子×ソース種別ごとに「人が書く素直な最速ループ」を書き、FLinq・ZLinq と同じ行に並べて比べる。
- FLinq と同じ前提の下での下限になるよう書く。FLinq のほうが確実に速い行は、理想版の不備として理想版を直す。

## 前提は FLinq の `.Anchor` 契約と同じ(2026-10-02 改訂)

FLinq は既定で積極的に最適化し、`.Anchor` を書いた式だけ評価の回数・順を変えない(`docs/refactoring-designs/20260624-1806-flinq-intercept-optimization-pipeline-fragment-spec.md` の Anchor policy)。理想版も同じ前提で書く。

- `.Anchor` を書いていない式(ラムダの本体・ソース式)は、副作用が無く、決定的で、例外を投げないとみなす。評価の回数・順・有無は自由に変えてよい。
  - 結果に使われない評価は書かない(例: 結果選択子が使わない要素選択子、結果を捨てる呼び出し)。
  - ループの外へ出す・並べ替える・まとめる・同じ純粋な式の結果を使い回す。
  - 値を使った数式への置き換えもしてよい(Range の偶数の個数を個数と端から求める、和の公式、単調な選択子の最小・最大を端から求める、`x%1000` のような構造からグループや順序を直接作る)。
- `.Anchor` を書いた式は、System.Linq と同じ回数・同じ順で評価する(2026-10-02 時点でベンチに `.Anchor` は無い)。
- 演算子そのものが定める結果と例外は System.Linq と揃える。空の `First` の例外、`ToDictionary` の重複キー、`Single` の重複、安定ソート、集合演算の出力順、グループの初出順など。結果ダイジェストが ZLinq(複合連鎖は全最適化版)と一致することをテストで検査する。

## 使ってよい事実

- ソース式の形から分かること: 配列・List の長さと添字、Range の個数・範囲・添字・値が一意で昇順であること、同じ純粋な式は同じ値になること(例: 同じ `srcCount(n)` 同士の `SequenceEqual` は true)。
- 上の純粋性の仮定から導けること。
- 使わない: ベンチのデータ生成の中身を知っていること(`srcCount` が何を返すか、シードでどう並ぶか)。配列・List・IEnumerable の値は読んで処理する。

## ベンチの枠は FLinq と同一にする

- 反復回数(`IterationCount`)、ソースの取得(`srcCount`・`src2Count`・`srcOne`・`srcMinusPlusCount`・`srcNestedCount`)、順序依存ベンチの `ExecuteOrderDependent(() => this.X_Impl())` の包み、`consumer.Consume` の呼び方は `Shared/Linq.Enumerable/Base.cs` と同じにする。
- 理想化するのは `X_Impl` の本体だけ。定数と補助関数(`Number`・`Mod` など)は `IdealBase.cs` に写し、写しのずれはテストで検査する。
- メソッド名と具象型の直接の基底型名(`Array<T>`・`List<T>`・`IEnumerable<T>`)は既存と同じにする。行の突き合わせに使われる。

## 使ってよいもの・いけないもの

- 使ってよい: BCL の公開 API(`Array.Sort`・span の `Sort`、容量指定の `HashSet`/`Dictionary`、`CollectionsMarshal`、`MemoryExtensions` の検索・比較、`Vector<T>`、`ArrayPool`)。
- 型による特殊化は `int` などのプリミティブ型だけ(`typeof(T)==typeof(int)`)。ベンチ固有の型(`ClassInt32`)向けの特殊化はしない。
- IEnumerable 起点では、静的な型から分かる以上の実行時の型判定はしない(例外: 演算子そのものが判定である `TryGetNonEnumeratedCount`)。
- ソースの形から桁あふれし得ない件数・合計には `checked` を付けない。値によって桁あふれし得る合計(System.Linq が例外を投げるもの)は `checked` のまま。
- 使わない: System.Linq・ZLinq・Seamless の LINQ 実装の呼び出し(テストで検査する)。

## 結果に現れない中間物は作らない

- `ToArray().Consume(...)` の配列、結果選択子が使わないグループ要素の保存、結果選択子が内側を使わない `GroupJoin` の探索表と内側の列挙などは省く。
- `ToDictionary` は重複キーで例外になるので、全件を入れてから列挙する(例外の前に消費しない)。
