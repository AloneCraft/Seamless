# ブランチの分岐元と統合先

保守系列は `main → 0.1 → 0.1.0` とする。

| ブランチ | 分岐元 | 子の変更を戻す先 |
|---|---|---|
| `main` | なし | なし |
| `0.1` | `main` | `main` |
| `0.1.0` | `0.1` | `0.1` |

機能枝を追加するときは、実際に分岐した親ブランチと分岐点のコミットを記録する。戻す先はその親とする。`A → B → C → D` の場合、`D → C → B → A` の順で統合し、途中の親を飛ばさない。親に先行変更がある場合は、親の現在の先端へ戻す。

2026-10-30の整理では、共通履歴をmainへ統合した後に0.1を作り、続いて0.1から0.1.0を作る。作成直後は3枝が同じコミットを指す。Git自体はブランチの親関係を保存しないため、この表はブランチ運用の規則である。

作業ツリーで利用中の旧ブランチは、内容・index・HEADを保護して保持する。旧IDと正しい親系列の対応は統合監査のCSVを参照する。旧ブランチをそのまま新しいmainへマージすると、退避した旧トポロジーを再導入することがある。残作業を取り込むときは、保全・レビュー・検証を行い、対応する修正済みの親系列へ載せてから上記の順で戻す。

未完成・実験中の変更は保全して保留する。完了していない検証を成功として扱わない。退避済みの旧参照は `archive/20261030T053031Z/` 配下のGitHubタグと、ローカルのbackup参照から追跡する。
