# Benchmark Dynamic UI デバッグ起動エラーの記録

利用者から報告された起動エラーを発生順に追記する。観測事実、原因の推定、対応と確認結果を分け、同じ原因だと確認できるまでは別の事象として扱う。

## 2026-11-06: Release ビルド時の DLL ロック

- 症状: `Benchmark.Dynamic.Infrastructure.dll` のコピーが、`Benchmark.Dynamic.UI` の PID 28832 によるロックで失敗した。
- 確認: 利用者が Release アプリの実行中だったことを確認した。実行中の出力先にはビルドできない。
- 対応: 実行中のアプリは停止せず、Debug 構成で調査を継続した。Release の再ビルド時は対象アプリを終了する必要がある。

## 2026-11-06: NuGet 復元エラーと構文エラーの表示

- 症状: IdentityModel 関連など 10 パッケージに対象フレームワークがないと表示され、ソリューション復元が失敗した。構文エラーも報告されたが、ファイル名と行番号は不明。
- 確認: 10 パッケージの展開済みキャッシュから DLL が欠落し、同じパッケージのアーカイブ内には DLL が存在した。欠落の原因は不明。
- 対応: アーカイブから欠落 DLL だけを復元した。認証プロジェクトと隔離出力でのソリューション復元、および Debug の復元・ビルドが成功した。構文エラーは Debug ビルドで再現せず、実際のデバッグ起動は未確認。

## 2026-11-06: Release デバッグ時に dotnet --info が失敗

- 症状: VS Code のダイアログに `Error running dotnet --info: Error: Command failed: dotnet --info` と表示された。後続のメッセージは文字化けしており、詳細は判読できない。
- 確認: `C:\Program Files\dotnet\dotnet.exe --info` は成功し、SDK 10.0.401 が存在する。C# 拡張は SDK 検出時に設定されたディレクトリがなければ `dotnet` を PATH 経由で実行する。VS Code プロセス自身の PATH は未確認で、原因は確定していない。
- 対応: ワークスペースに SDK ディレクトリを指定し、Dynamic UI の Debug / Release ビルドタスクにも同じ SDK の実行ファイルを指定した。PATH から SDK ディレクトリを除く実験では、`dotnet` の名前による起動が失敗し、絶対パスによる起動は成功した。実際の VS Code デバッグ起動による確認は未実施。
