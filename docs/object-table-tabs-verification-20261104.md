| 構成 | 関連テスト | 管理GUI | 生成したC#プロジェクト |

22件には外部ソース同期13件、設計4件、削除差分3件、管理サーバー・GUIシナリオ2件が含まれる。GUIシナリオは、読み取り集計の有効・無効の両条件で4プロセスを起動する。証跡は`F:\CodexTemp\SeamlessObjectTabs-20261104-01\verified`に保存した。再実行は`tools/management/Test-SourceWorkspace.ps1 -Configuration Debug`または`-Configuration Release`を使う。

初期の失敗テストで、表設計が`Window`に依存することを確認した。UserControlへの変更後、同じタブで表を閲覧・編集し、同じ表を再度開いてもタブが重複しないことを確認した。外部変更とGUI編集を区別する同期基準、保存応答の内容照合、削除差分のみの取消について単体テストも追加した。

GUIテストは実アプリの内部操作とWPF描画を使った。OSのマウス・キーボード操作は行っていない。一つのプロセスに新旧のシナリオをまとめた版は、Debugの一方の条件で従来の60秒上限に達した。この上限を維持し、DB作成・外部連携、再起動後の表編集、監査・利用者切替、閲覧専用の4プロセスに分けた。前のプロセスが保存した作業記録を、同じ隔離サーバーへ再接続する次のプロセスで読み直す。

- DB作成、C#プロジェクト生成、外部保存の定期取り込み、未適用と明示適用の区別を確認する。
- 再起動後に外部保存済みの列名で構造を表示する。別タブの変更を保持して編集し、削除予定の登録・取消を行う。複数表をまとめて保存すると公開版が一つ進むことを確認する。
- 削除の確認を取り消すと稼働版が変わらず、明示確認するとバックアップが存在し、確定済み表示と公開版が一致することを確認する。
- 無効な入力を作業記録から再開する。対象宣言が外部で変わった場合に、C#とGUI入力の両方を保持する。
- 実際に利用者を切り替え、前の利用者の表タブとC#が残らないこと、閲覧専用利用者へ本文を返さないことを確認する。

試験データはGUI用の隔離DBであり、行編集画面からの自己参照・循環参照データ投入は対象にしていない。オブジェクト単独保存と依存タブ選択、稼働版と下書きの左右比較、Linux、VS Codeの実画面操作は合格に含めない。[現在の操作と範囲](object-table-tabs.md)を参照する。
