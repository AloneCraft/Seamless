# テーブルの閲覧・設計・一括保存

ツリーや一覧からテーブルを開くと、同じオブジェクトのタブに構造を表示します。稼働版は参照用です。「このタブで編集」で個人の下書きへ切り替えると、同じ場所で列・主キー・関係を編集でき、実際のC#を確認できます。「テーブルを作成…」も設計ウィンドウを開かず、追加用のタブを作ります。

`*`は稼働DBへ未適用であることを示します。追加・編集・削除予定はアイコンと文字でも区別します。タブの×は画面を閉じる操作です。定義、外部プロジェクト、下書きは保持します。「閉じた下書きを再開…」から、C#をまだ生成できない新規表の入力も再開できます。作業記録は接続インスタンスと利用者ごとに保存します。別のManagerが同じ作業記録を更新していた場合は上書きせず、現在の入力を競合用のファイルへ退避します。

有効な設計はC#と個人下書きに保管します。外部プロジェクト連携中は同じ`.cs`にも反映します。保存済みの外部変更と競合する場合は、元の宣言を再確認して保管を止めます。外部エディター、管理ツール内のC#、構造編集が同時に変わった場合も、編集を始めた基準と保存された版を比較します。

「削除予定にする」は対象の削除を下書きに記録します。元の構造を表示したままタブの内容に「削除予定」を重ねます。この時点では稼働DBのデータを削除しません。「削除を取り消す」は記録した宣言と移行定義だけを戻します。周囲の宣言や行型が変わり、位置・型を確定できない場合は保留します。適用済みの削除は、同じ取消ではデータを復元できません。

「このDBをすべて保存…」は、そのDBの入力とソースをまとめ、既存の差分・影響確認から一括適用へ進みます。閉じたタブを含め、C#へ反映できていない入力があれば保留します。データの削除を含む適用は、影響を明示して確認し、サーバーでバックアップを取ります。他のDBの変更を一緒に公開しません。下書きの保管、外部ファイルの保存、タブの選択だけでは移行しません。

現在はDB全体の一括保存までです。選んだオブジェクトと依存タブだけの保存、稼働版と下書きを左右に並べる比較、行データ編集の取引画面、競合した作業記録の差分解消は残っています。対応範囲と受け入れ条件は[オブジェクトタブ設計](refactoring-designs/20261103-object-tab-drafts.md)を参照してください。
