# テーブルの閲覧・設計・保存

左の「通常のデータベース」を右クリックして「新しいデータベース…」を選ぶか、分類名の横の「＋」を押します。追加された行で名前を入力し、「作成」を押すと空DBが公開されます。Enterは名前を確定し、F2で再編集、Escapeで取り消せます。

DB・スキーマ・「テーブル」分類を右クリックし、「新しいテーブル…」を選ぶと、その場所を対象に追加用のタブを開きます。DBを表示したときは見出し近くの「このDBにテーブルを作成…」からも進めます。既存のテーブルは右クリックの「設計を編集」または「削除予定にする」から操作できます。ツリーと一覧のメニューは、右クリックした項目を対象にします。systemは構造の参照専用です。

ツリーや一覧からテーブルを開くと、同じオブジェクトのタブに構造を表示します。稼働版は参照用です。「このタブで編集」で個人の下書きへ切り替えると、同じ場所で列・主キー・関係を編集でき、実際のC#を確認できます。上部には下書き、検証・実行、サーバーの共通メニューと、作業中の対象を表示します。

編集中の「稼働版と比較…」で、左に版番号付きの稼働版、右に編集できる下書きが並びます。列を選ぶと、変更前後で対応する列も選択されます。「C#を並べる」と、左右とも対象の表の宣言・行型・キー型へ切り替わります。入力が無効で右側のC#を生成できない場合は、診断を表示して入力を保持します。「稼働版を更新」でサーバーの現在版を取り直せます。

`*`は稼働DBへ未適用であることを示します。追加・編集・削除予定はアイコンと文字でも区別します。タブの×は画面を閉じる操作です。定義、外部プロジェクト、下書きは保持します。「閉じた下書きを再開…」から、C#をまだ生成できない新規表の入力も再開できます。作業記録は接続インスタンスと利用者ごとに保存します。別のManagerが同じ作業記録を更新していた場合は上書きせず、現在の入力を競合用のファイルへ退避します。

有効な設計はC#と個人下書きに保管します。外部プロジェクト連携中は同じ`.cs`にも反映します。保存済みの外部変更と競合する場合は、元の宣言を再確認して保管を止めます。外部エディター、管理ツール内のC#、構造編集が同時に変わった場合も、編集を始めた基準と保存された版を比較します。

「削除予定にする」は対象の削除を下書きに記録します。元の構造を表示したままタブの内容に「削除予定」を重ねます。この時点では稼働DBのデータを削除しません。「削除を取り消す」は記録した宣言と移行定義だけを戻します。周囲の宣言や行型が変わり、位置・型を確定できない場合は保留します。適用済みの削除は、同じ取消ではデータを復元できません。

「このDBをすべて保存…」は、そのDBの入力とソースをまとめ、既存の差分・影響確認から一括適用へ進みます。閉じたタブを含め、C#へ反映できていない入力があれば保留します。データの削除を含む適用は、影響を明示して確認し、サーバーでバックアップを取ります。他のDBの変更を一緒に公開しません。下書きの保管、外部ファイルの保存、タブの選択だけでは移行しません。

「この表を保存…」は、選んだ表と外部キーを成立させるために必要な変更だけを公開します。確認画面に、今回保存する表、改名・削除、変更の影響を表示します。対象表に入力途中の内容があれば、入力の確認を求めます。成功すると適用済みの表の `*` が消え、対象外の編集は同じ作業C#と個人下書きに残ります。削除予定の表では「この表の削除を保存…」から同じ確認に進みます。単独保存に対応するサーバーで表示します。

外部プロジェクトを連携しているときは、公開要求を送る前に操作IDを作業記録へ保存します。切断後は再接続時に結果を照会し、確認できた稼働版と個人下書きで表示を更新します。結果不明の間は、サーバーの下書きと照合する必要があるため、このDBの同期と再適用を保留します。

「行データを表示」で、同じ表タブに稼働版の行を表示します。「構造を表示」で元の設計へ戻ります。行の直接表示には `View` と `ReadRows`、変更にはさらに `WriteRows` が必要です。取得範囲を絞る場合は主キーをJSONで指定します。行のセルには数値や `null` を入力でき、文字列は二重引用符で囲みます。

「このDBの行変更を確定…」は、同じDBで入力した変更を表ごとに表示し、確認後に一つの取引で確定します。自己参照・循環参照は取引の最終状態で検査します。行入力はManagerの起動中に保持し、タブを閉じても再び開けます。アプリを終了するときや接続先・利用者を変えるときには、未確定の行入力がある場合に確認します。行入力に影響する構造変更は、行を確定または取り消すまで公開を保留します。通信失敗で結果を判断できない場合は操作IDを表示し、同じ変更の確定を止めます。

同じC#ファイルの競合は[外部ソース連携の競合解消](external-source-workspaces.md#復旧と競合)から確認できます。無効なテーブル設計や複数のManagerが同時に作ったテーブル作業記録の差分解消は残っています。対応範囲は[オブジェクトタブ設計](refactoring-designs/20261103-object-tab-drafts.md)を参照してください。
