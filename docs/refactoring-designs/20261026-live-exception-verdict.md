# ライブの例外一致表示

ライブのseed 0x1018_2026では、WorkerがSucceededと記録した例外一致のクエリを画面が「要調査」に数えていた。WorkerはExpectExceptions指定時に全経路の例外型を比較し、同型ならSucceeded、異なるならSemanticMismatchにする。一方、画面はexceptionsが空でなければ比較結果に関係なく不一致にしていた。

画面はWorkerのcomparisonsを使う。一つ以上の比較があり、すべてisMatchなら結果・例外の一致とする。比較なしは一致にしない。例外の存在は診断へ表示し続け、状態Succeededと全経路一致の両方を満たす場合だけ合格にする。架空の時間は作らず、例外一致のケースは時間測定なしのまま保持する。

同型一致、型などの不一致、未比較を回帰検査する。Worker側の例外比較規則や生成器は変更しない。
