# プロファイルの証拠版と同梱データの分離

## 背景と合意範囲

利用者が承認した `20261025-benchmark-profiles-strategies-consolidation.md` の「測定済み標準値を同梱」「コード・条件・証拠の不一致はMinimumへ戻す」を成立させるための実装詳細である。公開APIの優先順位、保存先D/F、計測回数、共有DBの原本保全は変更しない。

## 観察した問題

- `Profiles/measured.json` の同梱候補には `Evidence` がなく、現行実装では適用できない。
- `ProfileEvidence.Current.LibraryVersion` はExecution DLLのMVIDである。同梱JSONを埋め込む変更やGitリビジョンのメタデータ変更でもMVIDが変わるため、同じ候補を同梱して再ビルドすると、その証拠が失効する。
- 保存先を区別する `StorageKey` は、2026-10-26の修正 `15db605e` で追加した。これは引き続き必須条件とする。

## 設計

- ビルド時にライブラリのソース・プロジェクト定義・共通ビルド定義、復元済み参照のパッケージID/版、SDK、構成、コンパイル定数からSHA-256を作り、Executionの生成定数へ格納する。コードとコンパイル条件を変えれば証拠版が変わる。GitコミットIDとプロファイルJSONは入力にしない。
- 対象は `Seamless*` のC#・プロジェクト定義と `Shared/Common`、ルートの共通定義とする。bin/objの生成物は除く。実装を含まない文書・テスト・履歴の更新だけでは証拠版を変えない。
- `LibraryVersion` を `execution-source-v3:<SHA-256>` とする。旧MVID形式を互換扱いせず、旧証拠・旧測定は保持する。
- 標準JSONを `Seamless.Execution.Profiles/measured.json` として成果物・publish・NuGetへ同梱する。実行時はアプリの配置先から読む。DBは不要であり、同梱ファイルがない場合は候補なしとしてMinimumへ戻す。
- D/Fの同条件・別入力による実測と改善比較を通過した候補だけを同梱する。適用範囲は実測した型・件数・処理・保存方式・ボリューム・環境・構成に限定する。未検証の環境へ拡張しない。

## 移行と検証

1. 現行JSONをWorkへ保全する。共有DBは整合したバックアップを保持する。
2. 証拠定数と同梱ファイルの配置を実装し、Execution・共通基盤・Scalableの回帰を実行する。
3. 同じ入力群でD/Fを直列測定し、7回の有効値・中央値・ばらつき・独立入力の検証・5%以上の改善を満たす候補を出力する。
4. 候補JSONだけを同梱へ反映し、再ビルドして証拠版が不変であること、DではD用・FではF用を選ぶことを確認する。
5. NuGetの内容と独立consumerのコピー・実際の採用を確認する。ソリューションとアプリのDebug/Releaseビルド、関連回帰を確認してコミットする。pushしない。

## 制約

標準JSONは独立した同梱ファイルであり、ライブラリDLLだけを手作業で配布した場合には候補がない。通常の参照・publish・NuGetで一緒に配布する。候補の更新だけでコード版を変えず、コード版が変わる修正では再測定する。
