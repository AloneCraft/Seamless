# Pipeline段内の関数と入れ子のrender context

PipelineEnumerableの各段にあるFunc/SecondFunc/ThirdFunc/AggregatePlan.InnerFuncは、通常のchild関数と同じvisitorへ公開する。既存Funcs列挙をGetChildFunctionsへ接続し、stage内のInlinedScalarFunc.ScalarFragmentにもrender contextを再帰伝播する。counter/Anchor/Accessor探索に別々のfragment treeを作らない。

これにより入れ子のWhere/Select等も親メソッドの計測設定に従う。可視query lambda総数は利用者が承認した入れ子を含む定義を維持し、期待を外側だけに戻さない。値・例外・trace・Disposeの意味は別に検証し、計測だけの成功を全体の意味一致にしない。

無述語First系のsingleton需要を持たない従来OrderingBaseの問題は独立した変更として受け入れる。本変更単独の残件を隠さず、new source/generated/DLL/hashと回帰実結果はOrchestration台帳へ記録する。
## 補助コードを文字列化する前の計測設定

27のfresh生成ではchild visitor追加だけでは生成物と観測が25と同一で、内側の計測が欠けていた。構築時counter無効のStructMethod snapshotが先に保存され、後段の有効化より前の宣言が採用されるためである。FragmentBuildContextとPipelineBuildServicesは最初の文字列化から対象メソッドのCounterInstrumentationを継承し、再帰生成のForOuterTypeParametersでも同じ設定を保持する。同名宣言の重複除去順や期待値は変更しない。新しい生成SHAと内側の実callback数・operator counterの一致を別途検証し、runtime受入前の現時点では候補である。

## inline selectorの例外時の評価入口

31で通常6・二段の入れ子10と計測が回復したが、NoneのSelectが例外を投げると帰還後のRecordLogicalDelegateまで到達せず、実入口3に対して2になった。FuncAssignCurrentは既存FuncAssignでdestinationを設定してからout currentへ渡し、inline selectorの入口前加算を共通化する。destinationからout currentへの順序は従来と同じである。physical delegateの帰還後計測はこの修正に含めず別残件として扱う。既存strict fixtureと期待値を維持してfresh生成・例外・Dispose・回帰で検証する。
