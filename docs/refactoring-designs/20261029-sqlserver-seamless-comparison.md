# SQL Serverから再構築できるSeamlessDB比較環境

## 背景
2026-10-29、利用者が本チャットの計画全文を指定して実装を承認した。SQL Serverの実データを正本とし、SSMS、パッケージ利用EXE、型付き直接・リモートの4経路で比較する。

## 現在の実装と確認範囲
- Gateway は DB レジストリと共通 SQL 実行コンポーネントを使用する。動的 SQL の実行時 FLinq コンパイルは行わない。新しい TDS 型・照合順序・旧LOB対応は最終パッケージでの検証中である。
- 比較用の型生成は opt-in で実行ビューと主キーなし表の内部行IDを生成する。通常生成器の既定動作を変更せず、既存利用者との互換性を維持する。
- 元の17ユーザーDBに TPC_E と専用 fixture を作成し、検出対象は19DB、ビューは171。TPC_E は EGen 1.14.0／1000顧客／10営業日、33表・33主キー・48外部キーを実検証済みである。
- AdventureWorks2016 は全テーブル760,838行と20実行ビューの値一致を確認済み。全19DB・171ビュー、最新TDS経路、性能測定、SSMS実UIの受け入れは未完了であり、不完全な世代の切替は行っていない。
- C12 の Database/Generator/Transactions 契約を使用する。同じファイルの実競合がない限り並行作業を継続する。

## 過去設計から引き継ぐ仕様
20261029-generic-transactions-tpc-c12.md、20261026-three-chat-orchestration.md、docs/execution-and-database.mdを引き継ぐ。既存同期Commit/Dispose契約、新規SharedV2 opt-in、保存形式の互換性、資源予算と非干渉を維持する。本計画はGateway接続を追加するが取引本体/WALを別実装しない。

## 目的
- 毎回sys.databasesを検出して元DBの追加削除を追従し、元のDB/スキーマ/オブジェクト名を保存する。
- 初回は既存17DBと新規TPC_E。TPC_EはEGen 1.14.0、1000顧客、初期取引10営業日、33表。
- 比較DBは読取専用。CRUDと取引は両サーバーの専用fixture DBを使う。
- 全171ビューを定義から実行し、依存する関数を含め結果一致を検証する。保存済み結果による代替は禁止。
- 結果、時間、CPU、メモリ、I/O転送量を比較する。

## 非目的
任意のT-SQLストアドプロシージャ全般、TPC公式監査、任意DLLの要求ごとの受信、無停止切替、動的SQLの実行時FLinqコンパイルは対象外。

## 提案設計
### SQLとセッション
共通エンジンが構文解析・名前解決・SQL型検査・実行計画キャッシュを行う。SELECT/CRUD、5集計、GROUP BY/HAVING/ORDER BY/TOP/DISTINCT、INNER/LEFT JOIN、別名、複合条件、NULL、基本演算/CAST、パラメーターを扱う。既存ビューに必要なXML/nodes/value、APPLY、PIVOT、派生表、日付/文字列関数、依存UDFも追加する。未対応は実行前に明示拒否する。
キャッシュはDB/スキーマ世代/SQL/引数型を区別し有界とする。実行状態を保持しない。SQLの三値論理、集計の空集合、型、照合順序を守る。
LOGIN7、USE、DB_NAME、sysカタログを実DB登録へ接続する。SqlClient RPC/sp_executesql/prepare、取引管理、切断/reset、キャンセル、複数結果を検証する。結果は有界チャンクで送る。
### 型付きネイティブ
クエリ定義と通常C#の呼出入口を生成後、FLinqを適用して共通モジュールをビルドする。同じモジュールを直接実行とサーバーで使う。実行時はクエリIDと引数だけを送る。型付きproxy/引数/結果とmanifestを生成する。MemoryPackの長さ付きバイナリ通信、既定14335。TDS14333/HTTP8088。
manifestでモジュールハッシュ/パッケージ版/スキーマ指紋を照合する。FLinqの生成・実行を確認し、ディスク退避と予算の保証も別に検証する。
### 取り込みと世代切替
SQL型/NULL/列順/照合順序/定義/SQL実名とC#名の対応を保存する。値の暗黙丸め/切捨てを禁止。主キーなしは内部行ID付きの取り込み用ストレージで重複を保ち、既存Tableの集合契約は変えない。
新しい世代を別保存先へ作り、全表/ビュー/モジュール検証成功後だけサーバーを再起動して一括切替する。失敗は旧世代を維持し、切替後の正常性確認失敗は復帰する。
一覧取得成功かつ不存在のDBだけ、切替成功後に管理下の生成コード/データ/関連成果物を削除する。OFFLINEや権限/接続失敗は削除ではない。削除前に絶対パスと管理台帳を検証する。手書きSQL/C#は保全する。
ローカル保存は SSD の D:/Seamless/Comparison/Managed・Temp と、HDD の F:/Seamless/Comparison（フィード・パッケージ・操作ログ）へ分離する。C へのデータ出力を拒否し、依存の復元元も F または NuGet 公式にする。利用者の追加指示により、他チャットの処理終端確認後、共通 BGO 台帳を D:/CodexBackgroundOps、登録情報を D:/CodexBackgroundOpsRegistry に移管した。旧 C パスは実データを持たない互換ジャンクションとし、排他と調停器再起動後の所有権保持を実検証した。private mailbox は F に登録する。
元DB設定を自動変更せず、一貫した読取トランザクションを使う。スキーマ変更/取得失敗/未対応の新DBは事前診断し、部分世代を稼働させない。
### 再現環境
初期準備、再構築、比較、全工程をPowerShellで実行可能にする。TPC_E準備は通常再構築と分離し、利用者による削除後に勝手に再作成しない。
製品はSeamless.slnx登録の依存閉包から同じ一意版のNuGetへpackする。TestSeamless.slnxのEXE/テスト/クエリモジュールは製品をPackageReferenceだけで使う。ローカルフィード/専用キャッシュで実際のパッケージと生成器を検証する。直接実行は別データコピーを開く。
SSMSにはSQLServer/SeamlessDBの2プロジェクトとDBごとの接続、共通SQLケース、CRUD/COMMIT/ROLLBACKの再現を用意する。資格情報は設定/secret/envで解決し成果物へ埋め込まない。

## 影響範囲
Gateway/Server、SqlServer/Rdbms/Tool/Generatorの必要部分、新しい共通SQL実行/型付き通信、TestSeamless、主/軽量ソリューション、CI、操作文書。C12の変更を保全する。

## 移行手順
独立領域から実装し、製品とNuGetを先に作り、fixtureで統合する。その後TPC_Eを明示準備し、実DBを全件構築・検証する。既存保存先は直接書換えず新世代へ構築する。

## テスト計画
Debug/Releaseの製品・パッケージ消費・生成器・SQL・TDS・型付き通信・取引を検証する。全表は値/NULL/重複数、全ビューは実行結果を照合する。順序なしは多重集合、同順位の順序は要求せず、TOPは決定的なケースにする。
取り込み値と整数/decimal/文字列/日時は厳密比較。浮動計算のみ abs(a-b)<=absolute+relative*max(abs(a),abs(b))。real/singleはabsolute=1e-6,relative=1e-5、doubleは1e-12/1e-9。閾値は設定/報告する。
正しさ合格後にReleaseでウォームアップ2回/測定7回、同時接続1/4/16、SQL順交互。全結果受信までを測り照合は区間外。PID/生成時刻を確認しCPU時間/WorkingSet/PrivateBytes/I/O転送量を記録。背景混入とUnavailableを区別し物理ディスクI/Oとは称さない。JSON/CSV/閲覧用報告を出す。
DB追加削除/スキーマ変更/重複/NULL/大結果/失敗/切替復帰/古いモジュール/キャンセル/切断/resetを検証する。CI小fixtureと全実DB受入を区別する。SSMSファイル検証と実UI確認を区別する。

## リスクと対策
全ビューの依存構文を実カタログで固定する。現行の黙殺SQLや全件メモリ化を残さない。C12との実競合が確認されたときは本作業を停止・報告するが、相手が実行中という理由だけで止めない。BGOでsource/build/data/port/計測資源を調停し、他者プロセスを終了しない。
