# FLinq フォールバック検証の Dynamic への統合

## 背景
チェーンの結果・手書き理想コード・フォールバック禁止を Dynamic の実行経路に集約し、重複する静的テストを整理する。

## 現状の観察
Dynamic は生成時に FLINQ002、失敗マーカーと interceptor 欠落を検査し、正常実行時に EnumerableFallback を確認する。例外発生時はカウンターを保存せず、例外比較で成功する経路もある。旧 StaticChainIdealTests は静的生成の3ケースを手書きループで比較する。Dynamic の固定ケースと網羅チェーンは別の生成経路を通る。

## 過去設計から引き継ぐ仕様
20260702-fable5-flinq-enumerable-inventory の生成時と実行時の両検査を維持する。20260616-0946-tsavorite-linq-enumerable の storage-level の検証は単なる IEnumerable 判定と区別する。20261022-dynamic-verifier-consolidation の、旧ケースを移植して検証してから削除する方針と、意味・例外・評価回数の維持を引き継ぐ。

## 目的
Dynamic で正常・例外時の fallback を失敗として扱い、同一の入力、理想コード、検出条件を確認できた重複だけを統合する。

## 非目的
FLinq の実装・公開仕様の変更、異なる provider や静的コンパイルの検証を根拠なく削除すること。

## 提案設計
各実装のカウンターを例外時にも取得し、例外一致より先に fallback を失敗とする。Dynamic 固定ケースに旧理想ループと同じ式・入力を移し、System、最適化前後、ZLinq、理想を比較して fallback 0 を検証する。静的生成特有の保証が移行先にない間は旧テストを維持する。配列直走査の Sum は加算だけを checked とし、選択子の演算の checked 文脈は変えない。並べ替え後の Where が短絡する終端に到達する場合は、その Where を並べ替えの前へ移さない。

## 影響範囲
Dynamic Worker、Dynamic 固定ケース・テスト、必要なテスト文書。固定ケースは既存25件に旧静的テストの3件とフォールバック検証の2件を加え、全30件でZLinqも比較する。

## 移行手順
失敗する回帰試験を用意し、Dynamic の例外経路を修正する。固定ケースの対応を追加して検証し、等価性を実証できたものだけ整理する。

## テスト計画
正常・例外時の fallback 検出、例外一致、結果不一致、手書き理想と生成結果、既存のコンパイル診断を検証する。共有実行制約と既存の成果物・ロックを尊重する。

## リスクと対策
カウンターだけでは interceptor 欠落や別の実行経路を保証できないため、生成時検査を併用し、差分が残るテストは保持する。

## 未決事項
静的コンパイルと Dynamic で共通化できる保証はケースごとに実証する。
既存固定ケース chain-19 で検出した評価回数の増加は、短絡する終端に対して並べ替え後の Where を移動しない修正を加え、評価回数テストで検証する。
Join の PredicatePushdownShapeTests は、元の式を含む生成コメントと実行計画属性まで文字列検索していたため、実際の生成コードとは無関係に4件失敗していた。変更前の OptimizeVisitor を使っても同じ失敗を確認し、属性・コメントを除く構文トークンで形状を検査する。

## 合意状態
ユーザーの「dynamicに統合して」という実装指示に基づく。検証不足の削除は行わない。
