# 外部C#プロジェクトとManagerの下書き状態

## 方針

利用者はGUIでDBを作成してVS Codeのプロジェクトへスキーマを反映し、VS Codeでもビルドできる流れを求めた。利用者へ今は追加質問できないため、既決の双方向自動同期・三者比較・明示適用の方針と整合する判断を記録する。

「タブに*を付ける」と「下書きを復元可能に保存する」は両立させる。編集用の独立した第二の.csファイルを増やさない。外部プロジェクトが管理する通常の.csを共有する作業ソースとし、システムDBの個人下書き・基準版・同期履歴へ結び付ける。サーバー本体の.csprojを書き換える方式にはしない。

## 状態の意味

| 状態 | 外部ファイル | Manager | 稼働DB |
|---|---|---|---|
| 同期・適用済み | 保存済み | 印なし | 同じ定義 |
| VS Codeで保存 | 新しい内容 | 変更対象タブを開き、`*テーブル名`などで未適用を表示 | 以前の定義を継続 |
| GUIで変更 | 同じ.csへ自動反映 | 未適用、下書きを自動保存 | 以前の定義を継続 |
| IDEの未保存バッファ | ディスクは変更前 | ファイル監視では取得できない | 以前の定義を継続 |
| 競合 | 上書きしない | 差分・両側の内容を保持して解決待ち | 以前の定義を継続 |

`*`は稼働版へ反映していないことを示し、ファイルへの書き込みが済んでいない意味と混同しない。状態表示に「ファイル保存済み／下書き保存済み／稼働版に未適用」を出す。構造の適用と行データの取引確定は分ける。

下書きの自動保存は復元のためであり、ビルド・移行・公開を自動で実行しない。IDEで.csprojをビルドしても稼働版は変更しない。復元用のスナップショットや同期記録は編集用の第二の正本ではない。公開済みソース版は不変のまま保持する。

## 同期の動作

外部保存を検知し、最後の同期内容・現在の下書き・外部ファイルの三者を比較する。重ならない変更は統合して解析し、同じ箇所の変更は競合として保持する。GUIからファイルへ書いた変更を再検知して、別の編集として循環させない。ファイルとシステムDBを一度に確定できると仮定せず、同期状態・版・ハッシュと部分失敗を記録し、再起動時に照合する。

対象タブは背景で開き、コード入力中のフォーカスを奪わない。大量の変更では未適用変更一覧も使う。構文・型エラーではコード内容を保持し、最後の有効な構造は更新前と表示する。対応するテーブルを特定できない変更を推測で別のオブジェクトへ割り当てない。

保存・適用は既決どおりDB単位の一括を基本とする。単一タブの適用で必要な依存タブがあれば一覧を示す。無関係なタブは黙って適用しない。既存の個人下書きの所有者・基準版・競合検出・権限確認を迂回しない。

## 閉じる・取り消す・稼働版へ戻す

利用者がサイド会話から転送を明示依頼した仕様を引き継ぐ。未適用の内容を一律に稼働版で上書きする共通の「破棄」は設けない。

| 操作 | 範囲と動作 |
|---|---|
| タブを閉じる | 表示だけを閉じ、元ファイルと下書きを保持する |
| Managerで行った編集を取り消す | GUIからファイルへ反映した分も含め、Manager由来の変更だけを戻す。外部変更は保持する |
| このテーブルを稼働版に戻す… | 対象宣言の外部・Manager両方の変更を戻す。差分と失われる外部保存済み内容を示す。同じファイル内の別テーブルは保持する |
| DB全体を稼働版に戻す… | テーブル単位とは別の明示的な範囲として扱う |
| Ctrl+Z | 直前の編集の取り消し。全未適用変更の破棄とは区別する |

外部変更だけの場合、Manager編集の取り消しではファイルを変更しない。Manager変更だけならその変更を戻し、稼働版との差分がなくなれば印を消す。異なる箇所に両方の変更がある場合はManager分だけを戻す。同じ箇所の変更や相互依存で安全に分けられない場合は自動上書きせず、差分と両側の内容を保持して解決待ちとする。

例として、稼働版の「氏名」をVS Codeで「名前」へ変更し、Managerで「電話番号」を追加したとする。Manager編集の取り消しでは電話番号だけを戻し、名前への変更を残すため`*顧客`も残る。対象を稼働版へ戻す操作を明示した場合だけ両方を戻す。

状態は例えば「未適用：外部変更1件、Manager変更1件／ファイル：保存済み／下書き：保存済み」と表示する。外部変更を保持した結果として印が残ることをエラーと扱わない。

最後の同期内容・ファイルの版またはハッシュ・Managerの編集・外部保存内容を追跡する。ファイルを戻す直前に現在の内容を再確認し、未観測の外部変更を上書きしない。C#の取り消す部分を確実に特定できない場合は推測で書き換えず、復元用の下書き履歴を残す。

新規テーブルの取り消しも他の宣言を保持する。専用ファイルを削除する場合はその削除を操作内容に含める。他の未適用変更が依存する場合は影響を示し、無関係なタブを黙って取り消さない。

IDEの未保存バッファはディスクのファイルとは異なる。Managerがディスクを戻してもIDEの未保存バッファまで破棄したとは扱わず、その後に保存された内容は新たな外部変更として取り込む。

## 実装の確認状況

2026-11-04時点で`SourceArchive.Export/Import`はC#ファイルと版付きマニフェストの明示的な交換を実装している。Managerの自動ファイル監視、外部.csprojとの接続、外部変更によるオブジェクトタブの自動作成はまだ実装していない。Template配下の四プロジェクトと、管理定義からの生成・同期は同一の機能ではない。Kestrel移行の完了と混同しない。

## 次の実装・受け入れ

1. GUIで空DBを作成し、テーブルを追加する。稼働版と未適用変更の状態を記録する。
2. 管理定義を通常の.csprojへ対応付け、実際のC#ファイルを生成する。既存の外部ファイルは無断で上書きしない。
3. VS Codeのタスク設定を用意し、同じビルドコマンドを実行する。VS Codeの画面での起動とCLIによる同コマンドの成功を区別して記録する。
4. VS Code保存→背景タブ・未適用表示→下書き保存、GUI編集→同じ.csの更新を確認する。
5. 重複変更、無効なC#、ファイル削除、Manager終了中の外部保存、通信断、保存途中の停止、再起動時の復元を確認する。
6. 外部変更だけ・Manager変更だけ・非重複の両変更・同じ箇所の両変更について、各取り消し範囲と未適用の印を確認する。共有ファイル内の別テーブル、新規宣言の依存、IDEの未保存バッファからの再保存も確認する。
