# FLinqの中間ValueTuple化とGroupJoin

## 背景と目的

既存のgroup所有化で有効だった準備費用の共有をGroupJoinにも適用する。全FLinq入力経路で、内部の値受渡しに標準ValueTupleを使い、匿名オブジェクトの割当と生成する専用型を削減する。CPU内訳、group数と偏り、Spillまで同じ適度なデータ量で比較する。

## 契約

利用者が受け取る型、公開テーブルとビューのstruct、外部callbackとcomparerの型、評価順、Anchor、キーの等価性、返却groupの寿命を維持する。外部へ渡るか型を観測する匿名値は元の型を使う。大きい内部値もValueTupleを使い、同期範囲の安定した領域では読取り専用参照で渡す。可変入力、queue、非同期、Spillと所有権移転の境界では必要な値コピーを行う。

## 実装順

1. 変更前の計測とGroupJoinの返却列寿命を確認する。
2. 共通生成器で、シンボルに基づいて匿名型の要素とValueTupleの位置を対応させる。純粋な中間受渡しを優先し、型の外部露出時は元の型を維持する。幅の広い複合キーのハッシュは全項目を使用する。
3. 一般GroupJoinの借用と所有を分ける。DBの専用経路では分割Lookupから一致groupを取得し、確定件数を使う。外へ渡るgroupは内部識別子を使って一度だけ所有化する。クエリの終了時に作業領域と予算を返す。
4. 4,096／16,384行で比較し、JoinのCPU内訳、group数・偏り、予算を絞ったSpillを調べる。

## 検証

通常LINQの値、順序、評価回数、nullと空入力、group寿命と同一性、取消と例外、予算返却を比較する。実際の生成経路、生成中間型数とコード量を確認する。時間、managed割当、GC、保持量、予約量、Spillを分離し、反復して5％を超える性能悪化は原因を調べて該当経路を調整する。

NUMA、並列度自動選択、クエリ間の資源配分は後続。作業・データはD、ログとcacheはF、共通8論理CPU以内で実施する。
