# オブジェクトタブへのテーブル設計の統合

## 引き継ぐ仕様

`20261103-object-tab-drafts.md`と`20261104-external-source-draft-state.md`の仕様を維持する。オブジェクトの閲覧・設計は同じタブを使う。閉じる操作で下書きを削除せず、削除予定は内容の上に表示する。外部ファイルの保存・下書きの保管は稼働DBを更新しない。利用者が押すオブジェクト保存／すべて保存を、対象を検証・ビルド・移行・公開する明示操作へ接続する。

## 現在の実装と今回の順序

着手時は`テーブル設計 : Window`をShowDialogで表示し、外部ソース連携のタブはC#エディターへの入口だった。設計部品をUserControlへ移し、カタログ・外部連携・新規作成が同じテーブルタブを使うよう接続した。閉じた下書きの再開、削除予定・取消、DBをすべて保存する入口を追加した。[操作](../object-table-tabs.md)を参照する。

単独保存の外部キー依存範囲を `DatabaseDesigner.SelectTables` で求め、`PrepareTablePublication` で選択範囲のC#と移行定義から公開候補を作る。サーバーは `TablePublicationV1` を公開し、`previewTable` と `applyTable` を既存のコンパイル・移行・公開処理へ接続する。確認トークンは基準版、下書きの版と全内容、選んだ表、公開候補に結び付ける。公開確定時は操作結果と同じシステムDBの書き込みで、対象外の編集を保持した下書きの基準版を更新する。行型やファイル内の共有宣言など分離できない変更は明示的な選択か保留を必要とする。

依存範囲は、稼働版と下書きの外部キー・主キーを照合して決める。外部キーが新しい参照先やキーを必要とするときは参照先の変更を含める。親の削除・改名・キー変更で稼働中の参照が成立しなくなるときは参照元の変更も含める。既存のキーで参照が成立する場合は、親に別の列変更があっても対象に加えない。依存先を追加するたびに同じ判定を繰り返し、自己参照・循環参照を含む候補全体を既存のコンパイル・移行検証に渡す。

公開候補は稼働ソースに選択したテーブルのプロパティ・行型・キー型の構文を重ねる。新しいスキーマには選択範囲に必要な宣言だけを含める。既存ファイルの名前解決条件が同時に変わる場合や、共有宣言の変更が選択外のテーブルに波及する場合は診断して保留する。候補の移行定義と、下書きに残す移行定義は同じ対象表の対応関係から分ける。残る下書きの作業ソース全体を保持する。

Managerの表タブと削除予定の表示に単独保存の入口を置き、公開前に対象表と依存表を一覧で確認する。公開後はサーバーの稼働版と再基準化した個人下書きを取得し、作業C#を保持したまま同じタブの表示を更新する。外部プロジェクトを連携している場合、要求前に操作IDを作業記録に保存する。通信切断や再起動後は操作IDから結果を照会し、確定済みの版と下書きを照合できるまで当該プロジェクトの同期を保留する。

Windows Debug・Releaseで、候補生成と管理サービスの公開、既存の表設計・削除・一括適用を含む各25件が成功した。確定直前の失敗で旧版と全下書きが残り、成功時は循環する対象表だけが一つの版で公開され、管理領域を開き直した後も未選択の表が下書きに残る。実行ログは `F:\CodexTemp\SeamlessTablePublication-20261104\final-Debug` と `final-Release` に保存した。

## 編集内容の扱い

- 閲覧は稼働版を明示して同じ構造部品を参照用で表示する。編集へ切り替えた場合は同じタブに個人下書きを表示する。C#ソース権限がない場合は取得済みのカタログ構造だけを表示し、架空のソースを生成しない。
- 同じDB・同じ対象を再び開いた場合は既存タブを選択する。別タブの変更は共有するDB下書きへ蓄積する。
- 設計部品の変更を反映する直前に、表示元と最新の対象宣言を比較する。他オブジェクトだけの更新は保持し、同じ宣言への外部変更を推測で上書きしない。
- 入力途中の無効な設計も作業記録へ保持する。閉じる操作では編集用のファイル・下書き・入力内容を破棄しない。
- 削除予定は元の構造が読めるオーバーレイとタブの文字・アイコンで示す。「削除を取り消す」は当該削除の差分だけを戻し、他のタブや外部変更を消さない。
- 構造の表示やタブ選択だけでは行取得・関数呼出・ビルド・データ移行を行わない。
- C#を開くと対象宣言へ移動する。保存中に表示対象が変わった場合は、結果を元のDB・接続へ結び付け、現在の表示を上書きしない。
- 作業記録には入力開始時の宣言を保持する。C#の同期は編集開始時点も含めた三者比較を行い、保存応答は実際に保存された内容のハッシュへ結び付ける。

## 稼働版と下書きの比較

- 同じ表タブの構造画面で、左にサーバーから取得した稼働版、右に編集中の個人下書きを並べる。比較の開始時と「稼働版を更新」で共有版を照会し、取得した版番号を表示する。公開成功時は比較元を更新する。
- 構造とC#を両側で一緒に切り替える。左は参照用、右の構造は既存の編集・下書き保管経路を使う。C#比較では同じ表の宣言・行型・キー型を表示し、下書きのC#編集には既存エディターを使う。
- 追加した表の稼働側は空と表示する。改名時は移行定義にある変更前の表を比較する。無効な入力や競合で右側のC#を生成できない場合は、その理由を表示し入力を保持する。

## 行データの確定

稼働版の表データは `TableRowsV1` の `readRows` で、件数を制限した表示と主キー指定の取得を提供する。1回の表示は1〜1000行かつ行のJSONデータは約4MiBを上限とし、途中で上限に達したことを返す。取得時の稼働版と行のストレージ表現のハッシュを、変更を確定するときに照合する。参照にはDBの `View` と `ReadRows`、直接更新にはさらに `WriteRows` が必要になる。旧版でサーバー全体の全権限を持つ管理者も操作できる。公開問い合わせの `Execute` と定義下書きの `Edit` から、直接参照・更新を許可しない。システムDBの行データはこの入口から公開しない。

同じDBの追加・置換・削除を `commitRows` の一つの要求で最大1000件受け、既存のDBゲートと取引を使う。置換・削除の元の行を照合してから、表ごとに元のキーを削除し、新しい行を追加する。自己参照・循環参照はすべての変更後に検証する。監査が有効な世代では、既存の監査用WALへ同じ取引で結果を記録する。応答喪失時に変更を自動再送しない。

Windows Debug・Releaseで各18件が成功した。自己参照、複数表の循環参照、孤立行がある場合の全件取消、主キーの入れ替え、古い行と稼働版からの更新拒否、監査記録と再起動後の行データを確認した。TCP/TLSとローカルIPCでは、行の取得・確定と専用権限の検査を確認した。ログは `F:\CodexTemp\SeamlessRowEditing-20261104\permissions-Debug` と `permissions-Release` にある。

Managerでは同じ表タブに行データを表示し、複数表の行入力をメモリ上で保持して一括確定する。構造の変更が保留中の行編集へ影響する場合は、適用を止める。Windows Debugの実接続画面で、自己参照と二者循環を持つ三表の一括確定、孤立参照による全件取消と入力の保持、構造保存の保留を検証した。検証の作業領域、成果物、ログは `F:\CodexTemp\SeamlessRowUI-20261104-F` を使用した。

## 検証
