# 読み取り集計のメソッド情報と検索

## 背景と観察
詳細監査は名前空間・型・メソッド・シグネチャ・元メソッドのモジュール/トークン・値を除いたテンプレートを持つ。一方、通常読み取り集計は問い合わせIDとDLL識別だけを表示・検索するため、利用者がコード上の名前から探せない。

## 引き継ぐ仕様
複数語AND、大文字小文字を区別しない部分文字列検索、最大100行・4096レコードのページ取得、元ソースは許可された開発者だけという方針を維持する。問い合わせや任意のgetterを表示のために実行しない。取得できない情報を現在の定義から推測しない。

## 設計
AuditReadEntryの既存4引数のコンストラクターを維持し、任意のMethodプロパティを追加する。保存済みのqueryAuditを集計キーのCodeVersionで検索し、版・成果物の識別・値の上限を確認して、名前空間・型・メソッド・シグネチャ・モジュールID・トークン・クエリテンプレートを返す。メタデータがなければnullとし、識別が不一致ならエラーとする。元のアセンブリやソースを開いて実行・再解析しない。

名前とシグネチャは通常の管理閲覧対象、テンプレートの返却・検索一致は対象DBの編集権限も要求する。非公開のテンプレートの文字列を検索結果やページ判定へ混ぜない。公開名とテンプレートにまたがる複数語も、許可された範囲内でAND判定する。

一覧は問い合わせID・DB等の条件に加え、各メソッド項目と完全修飾名でも検索する。検索文字列は1ページ約1Mi文字までとし、上限による途中ページはHasMoreとカーソルで表す。メタデータのキャッシュは1要求64成果物までに制限する。現在の定義へ切り替わっても旧DLLに対応する名前を保持する。

GUIは問い合わせIDを残し、別の列で実行メソッドを表示する。行の詳細からシグネチャ・DLL・モジュール/トークン・許可されたテンプレートを確認できるようにする。情報がない場合は未登録、取得できない項目は未記録と表示する。サーバーはAuditReadMethodsV1を公開し、未対応の場合も問い合わせIDによる既存検索と案内を維持する。集計キー・件数・保存形式5は変えない。

## 検証と境界
先行テストで完全修飾名検索、項目をまたぐAND、ソース権限と検索による漏えい防止、旧/新DLLの名前、未登録、識別不一致、文字数上限と続きページを確認する。Windows Debug/ReleaseでAPI・TLS/IPC・GUI内部操作と描画を検証する。Linuxと1万クライアントの性能は未検証のまま合格としない。既存の未コミット変更を保護する。

## 検証結果（2026-11-04）
証跡は`F:/CodexTemp/SeamlessReadMethods-20261104-01`。先行5ケースはメソッド未取得・検索不一致・走査上限なし・識別不一致の未検出で失敗した。修正後は実行集計と保存の関連15件が成功し、管理機能全体は`all-Debug/Release`で各171件成功した。両構成の画面ビルドは警告0・エラー0。

同じ問い合わせIDでも旧/新DLLに対応する元の名前で検索でき、未登録はnull、不一致はエラーになることを確認した。静的コンストラクターが例外を投げるDLLのビルド情報を登録し、DLLの実行やファイルの配置なしで照合した。公開名とDB名などにまたがるAND、テンプレートの値除去、本文の権限がない場合の返却・検索一致の抑止も確認した。

大きなテンプレートを持つ300集計行では、文字数上限による0件の途中ページと続きを確認した。本文の権限がない場合はその長さを走査量へ混ぜず、300行を公開項目だけで検索した。キャッシュは64成果物まで、既存の行数上限と連番カーソルも維持した。

全体検証後に対応能力の公開・未対応案内・未記録項目の文言を追加し、`compat-Debug/Release`の関連7件で再確認した。TLSとローカルIPCで完全修飾名を取得し、TLSでは管理権限だけの利用者に本文を返さず、その語での一致も返さないことを確認した。WPF内部操作では収集設定あり/なしの両方で実行メソッド列・詳細・既知の欠落・未対応能力の案内を確認した。最新の描画は`compat-render-Debug/Release`に保存した。追加の画面ビルドも警告0・エラー0。

共通8論理CPU（`0xFF`）、データD・ログFの隔離領域を使用した。実運用DBは変更していない。ホストへマウスやキーを注入する実OS入力試験ではない。LinuxはWSL一覧で停止中のdocker-desktopのみだったため未実行。通常読み取りの既定期間、全通信入口・認可の統合、1万クライアントの性能は全体の残作業である。
