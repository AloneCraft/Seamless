# ManagerのDB名変更

## 背景と合意

左ツリーのDB行だけを名前の編集場所とし、コンテキストメニューから同じ入力を開く。Enterとフォーカス移動で確定し、Escapeと空欄で取り消す。右タイトルとタブは現在名に連動する。2026年11月8日の実装・ブラウザー確認の明示依頼に基づく。

## 観察と設計

Definition.Idは不変で、Definition.Databaseは保存済みソース・DLLのmanifestハッシュに含まれる。DefinitionVersionへ現在のDatabaseを追加し、既存JSONではDefinition.Databaseを既定値とする。成果物内のDefinitionはその世代の識別を保持し、接続名・認可・カタログ・依存関係には現在名を使用する。実行枠と開いたDBはDB定義IDをキーとする。

専用RenameDatabase APIは対象のカタログID、期待する現在名、新名、操作IDを受け取る。対象DBの実行枠で処理を待ち、管理取引で現在名、依存クエリ、個人下書き、検証DB、利用者のDB権限、操作結果と履歴を一括確定する。同じ操作IDの再送は同じ結果を返し、異なる要求への流用を拒否する。同名、system、権限不足、期待名の不一致を拒否する。新名に予め設定された別の権限がある場合は意図しない権限取得を防ぐため競合として拒否する。

未公開クエリの下書きは接続名変更で改訂を進め、古い検証・取り込み成果物を使用した適用を拒否する。公開済み定義の編集は不変IDから現在名を解決する。名前変更後の通常公開でも現在名を保持する。新規DBは空いた旧名を利用できる。

## 互換性と不変条件

既存世代のDLL、manifest、ソースとデータの対応を保持する。管理メタデータは既存のJSONレコードとWAL取引で記録し、保存テーブルの構造変更を伴わない。名前変更の前後は一つの取引で公開される。外部からの旧名要求は現在の名前解決に従い、別DBへのすり替わりをDB ID照合で拒否する。履歴上の過去の名前は保持する。

管理履歴の閲覧権限はDatabaseDefinitionIdから現在のDB名を解決する。名前変更時に旧形式の未関連付け履歴を同じ管理取引で関連付け、空いた旧名を再利用した別DBの利用者へ履歴を渡さない。既存履歴の関連付けは履歴走査を伴い、大量履歴での時間・管理取引の予算上限は未測定である。

組み込み・所有者IPCの主体は同名のアプリ利用者と独立した権限を持つ。利用者別認証の主体は受付時に現在の権限と有効状態を再確認する。行アクセスの認可とDB IDの確定は同じ管理ロック内で行い、実行枠取得後に接続名が別DBを指していた場合は拒否する。

DB変更と結果不明の名前変更がある間は新規DB入力を開始しない。通信結果が不明な名前変更は同じ操作IDで結果を照会する。別DBへの切替時は問い合わせ・選択表・保持計画を解除して構造表示へ戻す。同じDBの再選択では実行表示を保持する。

## 検証

近接試験で成功、再送、同名、権限不足、期待名の競合、取消、権限の移行、旧名の再利用、成果物の保持と再起動を確認する。実DBの行・依存クエリ・継続編集を確認してから、Windowsブラウザーの通常操作で名前入力と結果を検証する。隔離DBを使用し、稼働する既存DBへ変更しない。DebugとReleaseを分けて記録する。

## 作業順序

利用者提示の1〜6のManager正常系を優先する。今回の対象は1とそれに必要な2。7〜13の基盤検証は関係する境界を組み合わせ、14〜21は既存実装と証跡を照合して後続へ接続する。Linux作業は利用者によるWindows再起動後に開始する。復旧ロックとメモリ不足は配布前の未解決ゲートとして維持する。

## 現在の状態

API、全管理アダプター、左ツリーのメニュー・F2・名前入力を実装した。WindowsブラウザーでEnter・blur・Escape・空欄、重複からの修正、新規DBのblur作成、スキーマのEnter・blur作成と下書き保管を確認した。既存の18オブジェクト入りコピーで名前を変更し、Itemsの2行、ItemList、OrderAmount(101)の46、dbo1.OrderAmount(101)の124を照合した。ブラウザー操作はDOMのラベル・文字列・入力値を使用した。

近接試験でDB切替時の旧結果表示、監査有効化時の旧名への復帰、所有者主体と同名アプリ利用者の混同、名前変更中・結果不明時の新規入力の競合、旧名再利用後の履歴権限を修正前に再現し、修正後の成功を確認した。

## 最終確認結果

証跡ルートは `F:/Seamless/db-rename-20261108`。最終候補は管理契約・共通UI・サーバーのDebug／Releaseビルドが警告0・エラー0、同じ対象の回帰試験が各52件成功・失敗0・スキップ0。近接試験には同期直接呼び出し、所有者IPC、管理取引の途中失敗、取消、同時変更、旧名の再利用、履歴の権限、旧JSON、継続公開、監査有効化、再起動を含む。

Windowsブラウザーでは隔離コピーのSchemaUiDemoを名前変更し、最終候補runtime5でSchemaUiVerifiedへ変更した。同じruntime5で正常停止・再起動し、新名・公開v4・Itemsの値 `1, Root.A, 11` と `2, Root.B, 15` を確認した。その前の再起動ではOrderAmount(101)の46も確認済み。別DBへの切替で旧問い合わせ結果が消えること、RenameCollisionの下書きに保存したtreeEnter・treeBlurが再表示されることも確認した。ブラウザーの検証項目は16件で、DOMのラベル・文字列・入力値を証拠へ記録した。
