# Manager定義編集グリッド

## 背景と合意

利用者がSSMSのような高密度のグリッドと矢印キー操作への変更を指定した。列名・入力可能な型候補・主キーを一行のセルへ配置する。20261107-manager-contextual-interaction.mdの行ハンドル・検索メニュー・下書きと明示適用を引き継ぐ。今回の実装指示を受けて進める。

## 実装からの観察

管理ワークスペースと問い合わせ設計はHTMLの設計表へ独立した入力欄を並べている。セルの余白と入力欄の枠が重なり、共通のセル移動がない。既存の型入力はユーザー定義型の直接入力と候補リストのキーボード操作に対応している。結果グリッドはDBの行編集・ページング・保存を担当する。

## 設計

共有Razorの編集グリッドへ見出しと行を渡し、セル内へ既存の入力・型入力・チェックを配置する。行高を28pxに揃え、セルの境界と選択位置を表示する。狭い幅では横スクロールして一行の構造を保持する。

JavaScriptのイベント委譲で選択セルを保持する。文字入力の内容を全文選択しているときは、矢印で上下左右のセルへ移り、移動先の入力も全文選択する。キャレットだけ、または部分選択のときは通常の文字編集へ渡す。F2は入力末尾のキャレット編集へ切り替える。TabとShift+Tabは隣のセルの入力を全文選択し、端ではグリッドの外へ移る。Enterは編集区切り、Escは編集開始時の値へ戻す。Spaceはチェックやラジオ選択を実行する。Shift+F10で既存の行メニューへ接続する。

空文字はselectionStartとselectionEndだけで全文選択とキャレットを区別できないため、セル移動で空入力を選んだことをWeakSetで記録する。ポインターでの入力操作、F2、入力変更、フォーカス離脱でこの記録を解除する。IME変換の開始から終了まで、変換キーと展開中のcombobox・menu・listboxの操作をグリッド移動へ変換しない。

ポインターで入力欄をクリックした場合は直接編集する。入力候補・コンテキストメニューが開いている間は、その操作を優先する。IME変換中のキーを横取りしない。行追加・削除後は残るセルへ選択を引き継ぐ。グリッド単位のイベントを破棄時に解除する。

## 影響範囲と移行

テーブル列、ビューの結果列、関数引数と、DBの結果グリッド内の行編集で同じ部品とJavaScript engineを使う。結果グリッドは見出し・行をRenderFragmentで渡し、表と枠のクラスを指定して従来のデータ表表示を保つ。既存の保存API、版・stamp、ページング、値型変換を維持する。既存行の入力が元の表示値へ戻ったときは、そのセルの編集差分を除去し、他セルの差分は保持する。再読込で別の行モデルへ置き換えるときは行keyも変え、古いセルの編集開始値を持ち越さない。

独立headless Chromeで共通engineのDOM試験6件が成功した。全文選択・キャレット・部分選択、F2・Tab境界、空セル、Esc、IME・combobox・select、動的な行追加とdisposeを確認し、利用者のブラウザーや稼働サーバーには接続していない。証拠は`F:/Seamless/visualization-20261109-0e63c1c7/grid-input-dom-r1/run`へ保存した。Razor接続と行差分取消はResultsGridOperationsの近接試験、通常Managerの実データ操作は新候補の受入で確認する。

## 検証

共有UIをコンパイルし、実際のManager画面で密度・横スクロール・矢印移動・編集確定取消・型候補・カスタム型入力・主キー切替・行追加削除を確認する。下書きの列値を再表示して入力結果と照合する。表示と操作はDOMの役割・ラベル・入力値で判定し、画面画像を保存する。

## 型補完とコード表示

型入力は直接入力と候補選択を共存させる。`global::`ではルートの名前空間と型、`System.Collections.Generic.`ではその直下の名前空間と型を表示する。ジェネリック引数の位置でも補完し、型の挿入後は最初の型引数を選択する。Ctrl+Space、Alt+↓、候補ボタンで開き、上下とEnter・Tabで選択する。名前空間の選択では次の階層を開く。

入力セルがフォーカスを持つときに候補を表示する。Escによるグリッドの値復元も入力イベントでモデルへ反映するが、フォーカスを外れたセルの復元で候補を再表示しない。候補を閉じるEscと、セルの値を復元するEscを区別する。

型入力でも全文選択中の通常矢印はセル移動を優先する。自動表示の候補はこの移動を妨げない。キャレット・部分選択での編集、Alt+↓・Ctrl+Space・候補ボタンによる明示展開では候補側がキーを扱う。空セルはグリッド移動で選択した場合だけ通常矢印で移動し、F2・ポインターによる編集と区別する。IME変換中とkeyCode229ではグリッド移動と補完を行わない。明示候補を閉じると全文選択の移動へ戻る。

実際の型入力初期化とグリッド初期化を組み合わせた独立DOM6件と、既存グリッド6件を確認した。候補状態のC#通知先は試験用bridgeを用い、型カタログの照会はこの試験範囲に含めない。最終の同一試験でR4固定JavaScriptは7件成功・5件失敗、修正後は12件成功。証跡は`F:/Seamless/visualization-20261109-0e63c1c7/type-grid-dom-r1/before-fixed-final`と`after-final`。稼働Manager・既存DBには自動操作していない。

標準型と現在のソース宣言に加え、開いたプロジェクトのSDKが解決した参照DLLをメタデータとして読む。DLLのコードは実行しない。参照情報はビルド成果物と復元情報の変更を基準に更新し、SDKや参照が未準備の場合も直接入力と標準型・ソース内型の候補を使える。取得できない参照がある場合はプロジェクト画面に型補完の状態と復元・ビルド・同期の案内を表示する。

DBのC#、プロジェクトのC#、問い合わせ本体は共通の色付きコード編集部品を使う。既存のRoslynでキーワード・文字列・数値・コメント・ディレクティブを分類し、Razorのエンコードを通して描画する。入力、行番号、色表示のスクロールを同期し、色表示の更新待ちには通常の入力文字を表示する。

行番号の全文は絶対配置し、入力欄の高さを押し広げない。色表示と行番号の表示領域は入力欄のclient領域に合わせ、色表示の本文と行番号だけをスクロール移動する。DBのC#画面は残りのウィンドウ高に合わせて入力領域を確保し、横スクロールバーをその下端に置く。小さいウィンドウでは120pxの入力高を確保する。問い合わせ本体などの短い入力は指定行数による高さと従来のリサイズを維持する。

生成コードの範囲選択は原文のUTF-16位置を保持し、textareaへ渡すときにCRLFと孤立CRをLFへ正規化した位置へ換算する。色表示から末尾の表示用LF一文字を除いた原文を使用し、正規化本文が入力欄と一致しない場合や元の範囲が不正な場合は選択しない。原文のハッシュにはtextareaの正規化本文を使わない。独立DOMの6件は修正前4件失敗、修正後6件成功。証跡は`F:/Seamless/visualization-20261109-0e63c1c7/generated-selection-dom-r1`。

独立したChromeのDOM試験で、長文200行の表示高、横・縦スクロール同期、ウィンドウリサイズと5行入力の高さ保持、色表示更新と監視解放の4件が成功した。共通JavaScriptのグリッド6件も同時に成功した。証跡は`F:/Seamless/visualization-20261109-0e63c1c7/code-viewport-dom-r1/run2`。稼働中Managerへの自動操作やDB変更は行っていない。Razorビルドと通常Managerでの確認は次の固定候補へ引き継ぐ。

## 下書きと公開テーブルの区別

左ツリーは編集中の定義を表示する。公開定義に存在しないオブジェクトには「未適用」を付ける。データ画面で下書きにのみ存在するテーブルを選択した場合は、未適用の説明と「定義を編集」「変更を確認」を表示する。公開済みテーブルの読み取りAPIを呼ぶのは、公開定義に対象テーブルが存在する場合とする。下書きの保存、画面の再読み込み、明示適用を経ても公開済み判定を分けて管理する。
