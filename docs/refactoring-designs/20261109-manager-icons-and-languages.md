# Managerの共通アイコンとブラウザー言語

## 合意と目的

利用者の11月9日の指示により、変更確認を含む操作ボタンとメニューへ共通の現代的なアイコンを付ける。ブラウザーの優先言語から日本語・英語を選ぶ。画面の操作・保存・認可は既存の共通機能へ接続する。

## 実装する境界

- SVGの共通コンポーネントを設け、同じ操作に同じ線画を使う。現在の文字記号によるアイコンを置き換える。
- ラベル付き操作のアイコンは装飾として扱い、読み上げ名は操作ラベルから得る。アイコンだけの操作には既存の説明・フォーカス・操作領域を接続する。
- 共通メニュー、パレット、ツリーの操作ハンドル、主要ボタン、プロジェクト・結果・管理画面へ適用する。
- 共通リソースに日本語と英語の表示文言を置く。通常のコンポーネント描画の中立リソースは既存の日本語とし、Web入口ではAccept-Languageだけからja/enを選ぶ。未対応言語・ヘッダー未指定では英語を選ぶ。
- ページのlang、メニュー検索、ラベル、入力案内、ツールチップ、画面状態メッセージを同じ言語へ揃える。DB名・利用者のソース・型名・診断の原文は利用者データとして保持する。
- 同居・組み込み・IPC経由のManagerは既存の同じWebホストと共通画面を使う。翻訳は各利用セッションのカルチャーへ結び付ける。

## 実装順序と確認

1. 共通SVGと操作メニューへ適用し、変更確認を含む主要画面へ展開する。
2. 共通リソースとWebの言語選択を接続し、日本語・英語の表示を揃える。
3. 共通描画でアイコン・操作名・キーボード経路と両言語を確認する。HTTPでは優先順位・地域指定・未対応言語・独立した利用者の言語を確認する。
4. Linuxの現在の確認用Chrome画面を再利用し、両言語の見た目とメニュー・正常操作を確認する。一時確認画面は終了時に閉じる。

分割WALの近接確認を継続する。今回の画面変更とWALの検証範囲は分けて記録する。

## 確認済みの範囲

共通SVGを操作メニュー・パレット・操作ハンドル・型候補・主要操作・管理画面へ接続した。保存は受け皿と下向き矢印、変更確認はチェック付き文書で表す。コマンドに明示したアイコンと表示名による既定アイコンを共通部品で処理する。

日本語・英語の508文言を埋め込みリソースへまとめた。権限・監査の語は文脈を分け、ファイル参照のBrowseと参照権限のReadを区別する。メニュー検索は現在の表示文言と既存の検索語を使う。lang属性・ログイン・起動案内も言語選択へ接続した。

標準のAccept-Languageプロバイダーがq=0の日本語を選ぶケースをRelease試験で再現した。HTTPフレームワークの解析結果から重み0を除外し、全候補を優先順位順で共通のカルチャー選択へ渡すようにした。地域指定・4番目の日本語候補・未対応言語・ヘッダーなし・異なる利用者の同時要求を確認した。

Windowsの最終近接はRelease30件、Debug9件が成功した。既存のメニューと破棄の21件は最終Releaseにも含む。Linux Releaseも同じ30件が成功した。証跡は`F:/Seamless/linux-desktop-recovery-20261109/manager-presentation-final`と`manager-presentation-linux`。q=0再現の`manager-presentation-release`と、APIの引数型を修正する前の`manager-presentation-release2`を最終成功へ含めない。

Linuxの正式publish出力`runtime-manager-languages`を別配置に作り、英語サテライトDLLと静的資産を確認した。旧サーバーを正常停止し、全領域バックアップと隔離コピーでDB一覧・定義の版・下書きのハッシュを照合してから、PID58836で実利用領域を再開した。管理保存形式は5である。

既存のChrome画面一つを再利用し、実ブラウザーの英語優先でen表示を確認した。試験用のページヘッダー指定ではjaへ切り替わり、両方でデータタブの操作と8メニュー全項目のSVGを確認した。その指定を解除し、実際のブラウザー設定による英語へ戻した。DB名LinuxUiDemoとItems、未適用の下書きを保持した。画像は`manager-icons-en.png`と`manager-icons-ja.png`、所有・照合記録は`manager-languages-rollout.json`。

技術診断と利用者のデータを原文で扱う境界を維持する。今回の確認を全W01〜W21や配布全体の完了へ広げない。

詳細表示の追加確認で、行数・列数・監査の詳細・設定の状態・同期の版表示に未翻訳の文言を確認した。53文言を追加して561文言へ揃え、動的な件数・版番号の翻訳5ケースとグリッド・問い合わせの英語描画を追加した。既存のグリッド試験は文字参照を復号して表示文字列を比較するように揃えた。最終はWindows・LinuxともDebug／Release各42件が成功した。内訳は表示・操作39件と更新監査のCLI・強制終了3件である。証跡は`manager-presentation-details-windows`と`manager-presentation-details-linux2`。

最終publish出力runtime-manager-detailsを用い、正常停止・全領域バックアップ・隔離コピーでの定義と下書きハッシュ照合後にPID80357で再開した。管理形式5を保持した。Linux Chromeの実設定en-US/enでは英語になり、設定画面の未翻訳ラベルは更新前8箇所から更新後0箇所になった。日本語は同じページへのAccept-Language指定で見出しと集計期間を照合し、指定を解除して英語へ戻した。元のDBデータ画面と未適用案内を保持し、画面数は1である。画像はmanager-details-en.png・manager-details-ja.png、ソース・試験・配置の照合はmanager-details-rollout.jsonへ記録した。

読み上げ名の新規行・既存行と、計画のコード位置ツールチップの3文言も追加して564文言とした。Linuxで再ビルドしたDebug／Release各18件が成功した。同じAnyCPU候補のWindows確認は、変更した表示・グリッドの各17件が成功した。変更のないHTTP言語選択は先行のWindows固有静的資産を使った42件の証拠を再利用する。Linux開発用静的資産マニフェストをWindowsで開こうとした初回18件の実行は17成功・1失敗であり、manager-language-accessibility-windowsに保持する。

最後の配置はruntime-manager-accessibleでPID86914。バックアップと隔離コピーの照合を経て管理形式5、DBと下書きを保持した。実ブラウザー一画面で英語の設定に日本語ラベルが0であること、日本語の見出しを確認して英語と元のデータ画面へ戻した。最終画像はmanager-language-final-en.png・manager-language-final-ja.png、ソース・追加試験と先行証拠の参照はmanager-accessible-rollout.json。

## 結果グリッドの行操作SVG

正式Linux r3の列移行画像で、行削除の絵文字が欠落文字として表示された。結果グリッドの削除と新規行取消を既存の共通SVGに接続し、文字フォントへの依存を取り除いた。ボタンの表示文言をtitleとaria-labelに使い、SVGを読み上げから除外する。既存のクリック処理と無効条件を保持した。

同じTestDLLで旧正式r3 UIはSVG欠落の新2件が失敗し、修正UI9DE4E96Cで新2＋既存5の7件が成功した。UI単独Releaseは警告・エラー0。静的資産と英語衛星は正式r3のSHAを維持した。Linux専用Chromeでは、正式Linux r3の他DLLとWindows製修正UIを組み合わせた別候補を使用し、18×18の共通SVG、操作の読み上げ名、削除予定の取消、新規行入力後の取消、元の2行と未保管変更0を確認した。初回は試験が列名Idを探し、実際のidと一致せず停止した。元の証拠を残し、同じ候補と隔離DBを正常再開して実DOMのラベルに揃えた。
