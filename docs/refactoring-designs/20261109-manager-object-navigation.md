# Managerのオブジェクト単位ナビゲーション

## 背景

利用者が手動操作中のWindows Browser Managerで、型セルの矢印操作、左ツリーの選択表示、右画面とツリーの一覧重複を指摘した。対象別UIと関数統合は2026年11月10日に承認された。

## 改修前に観測した問題

- 型入力のkeydownが上下矢印を先に処理し、親グリッドのセル移動へ届かない。
- `DBオブジェクトツリー`と`所属オブジェクト一覧`には子オブジェクトの選択状態を渡す契約がなく、内容を開いても対象行の選択表示へ反映できない。
- `管理ワークスペース.razor`の構造表示は所属先のオブジェクトカードを列挙し、左ツリーの一覧と重複する。
- 現行タブはDB文書に所属し、選択対象によってデータ・結果・実行計画・履歴を追加している。C#は文書内のソースファイル選択であり、対象structだけの編集とは異なる。

## 過去設計から引き継ぐ仕様

既存の下書き・検証・明示適用、共通管理API、混在スキーマと所属先別識別、型の手入力と補完、全選択時セル移動とキャレット編集を引き継ぐ。ビュー・関数に対応する計画と実行履歴、テーブルのアクセス履歴を区別する。

## 目的

ツリーを対象選択の入口へ集約し、選択対象の内容・定義・C#を同じ対象として操作できるようにする。重複機能を整理する。

## 合意した設計

利用者が提示した対象別の基本タブを出発点とする。

| 対象 | 基本タブ | 定義編集 |
|---|---|---|
| テーブル | データ・構造・C# | 構造とC# structの双方向編集 |
| ビュー | データ・構造・C# | C#本体から結果列を推論して構造へ反映し、結果の列名・型は読取専用で表示する。 |
| 関数 | データ・構造・C# | 引数とC#本体を編集し、戻り値から集合の列構造またはスカラーの単一型を読取専用で表示する。 |

DB選択時は公開版・下書き・変更確認と適用・ソースとの関連を表示する。スキーマ選択時は所属DB・名前・公開と下書きの状態を表示する。オブジェクト一覧とクエリ一覧は左ツリーへ集約する。

テーブルにはアクセス履歴、ビューと関数には実行計画と実行履歴を加える。登録クエリも関数へ統合する。対象ごとに文書タブを開き、同じ対象は既存タブを再利用する。初回はデータ、新規作成は構造を表示し、以降は対象ごとの編集と表示状態を保持する。

C#は選択対象のstructと処理本体を表示し、partial宣言は宣言元を切り替える。構造とC#はタブ切替時に同期する。解析できない入力はC#に保持して診断を示す。LINQから構造へ反映する範囲は入出力の型構造とする。ビュー・関数は実行ボタンで取得し、集合と単一値を戻り型に従って表示する。ビューはContainerのインスタンスプロパティへ公開する名前付き問い合わせ定義として扱い、結果行型・列挙用の型・定義展開と全体最適化の役割は[ビュー定義・専用型・最適化の確定仕様](20261110-view-query-integration.md#ビュー定義専用型最適化の確定仕様)へ従う。

関数の共通管理APIはFunctionsAsync・GetFunctionDetailsAsync・ExecuteFunctionAsyncとし、DB内メンバーと既存登録入口を識別した対象記述を使う。登録入口は既存の定義ID・版・成果物で解決し、検証済み元メソッドの型情報を使って引数と戻り型を返す。取引の列挙完了・取消・予算・認可を既存実行へ接続する。

## リスクと対策

所属変更の既存経路は、明示的なTableプロパティに対する移行元・移行先の対応と外部キー参照名の更新を持つ。一方、生成対象の型宣言、ビュー・関数の所属変更とC#参照の意味を保つ書き換えは未対応。移動先の同名メンバーへ意図せず束縛される可能性があるため、コンパイル成功だけを根拠に所属変更を確定しない。旧版の計画・履歴は旧対象のまま保持する。

DB全体のC#と対象structのC#では編集範囲が異なる。既存本文・コメント・別対象を保持できる境界を現行ソース同期と照合して決める。計画や履歴の既存機能は新しい入口を合意してから移す。

## 処理本体からの関数戻り型同期
