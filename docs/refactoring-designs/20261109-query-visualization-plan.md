## 目的

実際の複数クエリについて、選択対象、静的計画、式、中間関係、最適化、実行実績、元ソース・展開コードを対応付けて調べられる設計を定める。

## 非目的

DBの保存形式、取引、WAL、スケジューラを可視化専用に作り直さない。未観測の並列実行・物理方式・統計値を図の都合で補完しない。テーブル選択から問い合わせの実行を暗黙に開始しない。

## 提案設計

### 1. 対象ごとの画面と名前

| 選択対象 | 入口と表示 |
|---|---|
| DB | 構造・C#・クエリ一覧。従来のDB共通「計画」はクエリ一覧へ置き換える |
| クエリ一覧 | ビュー・関数・公開クエリを種類・所属・名前・公開版・計画の有無で一覧化し、対象を開く |
| テーブル | 定義・データ・アクセス履歴。履歴には読取・書込、利用者、時刻、問い合わせとの対応を、記録できた範囲で表示する |
| ビュー・関数・公開クエリ | 定義／C#、結果、実行計画、実行履歴。関数のスカラー／集合の違いは引数と戻り値の表示へ反映する |
| 内部メソッド | 親クエリの計画から辿る。メソッドに計画があることだけを理由に、公開実行できる扱いへ広げない |

実行計画は対象のコンテキストメニューとコマンドパレットからも開く。公開版、下書き、取り込み済みDLL、実行IDを画面に明示する。対象を変えたときは取得を取り消し、旧対象の応答を適用しない。

DB名を含む表示名の部分一致では束縛しない。DB定義ID、公開版／成果物ハッシュ、所属付きObjectId、正規化したメソッド署名を使う。オーバーロード、別スキーマの同名、共通ヘルパー、ビューの生成アクセサーとQuery本体を区別する。束縛不能・複数候補は診断として表示する。

### 2. データ契約と取得経路

既存の計画属性とPEリーダーを拡張し、次の責務を分ける。

1. 生成器・コンパイラーがノード、式、入力役割、意味のある接続、ソース・展開コード対応を記録する。
2. 管理サーバーが対象と計画の対応、公開版・権限・資源上限を確認して取得する。
3. 共通UIが表示用グラフへ投影し、レイアウトと選択状態を管理する。
4. 実行収集が実行ID・試行ID・ノードIDに実績を結び付ける。

スキーマ1は読み取り互換を維持する。接続種別・ポート・式・対応情報を追加する次の計画形式を版付きで導入する案とし、旧形式の未指定情報は不明として扱う。計画IDと実行IDは分離し、共有DAGのノードを複製して集計しない。

対象別の取得は既存PlansAsyncの利用者との互換を保つ入口へ追加する。最終シグネチャは生成器・PE・IPC／Web・ベンチマークの型共有を調べた後に確定する。UI内でC#やSQLの文字列から物理方式を復元しない。

### 3. グラフと意味

- 入力を上、結果を下へ配置し、同一段階は実際の入力役割・安定した順序で左から右に置く。
- 最下段は単一の表示用Result。実在する出力を対応付け、補助ノードの枠と説明を付ける。実行へGather等を挿入しない。
- データ、実行依存、データ要求、制御、同期、共有参照、ソース対応を別の接続種別とする。逆方向やループも種別と方向を保持する。
- 元の演算、採用された処理、変換判断、生成された条件を層として分ける。孤立した説明ノードを根拠なくデータ出力へ接続しない。
- Build／Probe、Outer／Inner等は採用方式の記録がある場合だけ表示する。動的な方式選択は候補と今回選択された枝を区別する。
- 独立した処理に通し番号を付けて逐次実行に見せない。配置、実行依存、実時刻を区別する。

既存RazorとSVG／HTMLの描画を基本案とする。レイアウト計算を表示から分離し、共有ノード、複数の出力、長い式、未知の接続を試験できるようにする。外部ライブラリの追加判断は代表的な大規模プランの測定後に行う。

### 4. 粒度・式・中間関係

粒度はクエリ概要、演算子、中間関係、数式、取得可能な実行内部とする。全体切替とノード単位の展開を設ける。

### 三段階の構造表示

利用者から、関係代数、式を含む論理処理、FLinq展開後のプログラミング要素という三段階の表示要求を受けた。現行の演算子・式の層を基に、次の構造へ拡張する設計案として扱う。

| 段階 | 内容 | 対応する情報 |
| --- | --- | --- |
| 関係代数 | 選択・射影・結合・集約・集合演算と中間関係 | 元の関係演算と採用された処理への対応 |
| 論理処理 | 算術・比較・NULL・短絡・出力式・条件 | 型と依存、評価条件、最適化前後 |
| 展開コード | 実際に生成されたC#のループ・分岐・goto・変数・Spanアクセス・バッファ操作 | GeneratedBodyHashへ結び付いた展開ソース範囲と制御フロー |

提案する初期表示は関係代数とし、ノードを選んで詳細な段階へ展開する。融合や分解があるため段階間の対応は複数対複数とする。切替・展開でクエリを実行しない。大規模な展開コードは初期表示から全要素を描画せず、対象と範囲を限定して取得・表示する。

展開コードの制御フローにはループの戻り辺がある。既存のDAG配置へそのまま渡さず、制御フローを扱う配置と、データ依存・制御・対応の接続種別を用意する。基本ブロックから命令・式を開き、生成C#へ移動できる構成を提案する。Span等の型だけからループやアクセスを推測せず、生成本文の構文と束縛結果から記録する。生成時に得られる静的構造と実行時に観測した回数・時間は別の属性として扱う。

現行は実際のFragment、PipelineStage、元の式と一部の生成条件を記録している。生成本文のhashは保持するが、全コードの構造・gotoの行先・ループ戻り辺・各生成範囲は未実装である。第三段階の追加と、三段階の選択UI・相互選択・往復保存・大規模表示の試験を後続の実装単位へ加える。受入では直接ループ、gotoを含む終端、Span経路、融合と共有を持つ実クエリを生成・コンパイル・実行し、表示の全要素が実際の生成本文に一致することを照合する。

**現行コードで確認したこと**

`FLinqIncrementalGenerator.InterceptorSourceWriter.cs`は、rename・local initializerの整理後の本文を`ExecutionPlanWriter.Append`へ渡す。その後`GeneratedSourceRenderCoordinator`が`GeneratedExecutionAnnotations.Apply`を一度適用し、本文へ手順コメントを加える。現在のGeneratedBodyHashはApply前の本文を指す。現在のRuntimeCondition収集は引数なしvoidメソッドの仮ラッパーへ本文を構文解析しており、実際の引数・戻り値・補助型を束縛したCFGを生成していない。生成器のanalysisCompilationは`DatabaseAnalysisCompilation.Create`でDB宣言を補完する。参照中のRoslyn5.6にはIMethodBodyOperationとSemanticModelからCFGを作るAPIがある。

**最小実装単位の提案**

最初は関係演算・元の式の表示に、実際の一つのinterceptor本文の文書と基本ブロック表示を接続する。最終renderと説明付与が終わったソースを、実署名・補助メンバー・型引数・unsafe・async・スコープを含むCompilationへ追加し、実MethodDeclarationのIMethodBodyOperationからCFGを取得する。生成時の計画ドラフトをrender後へ引き継ぎ、最終本文の採取後に属性を書き出す。型解決エラー、構文診断、CFG未対応は診断とUnknownを記録する。

Plan属性自身を含むファイル全体のhashには自己参照が生じる。既存GeneratedBodyHashの意味と束縛キーを維持し、別の最終本文hashと本文相対のUTF16範囲を加える。本文文書は属性外の実Method.Bodyを対象とし、属性のJSONが増えても位置が動かないようにする。Applyは一度だけ行い、最終属性の設置で再度の説明付与を行わない。補助メソッドは別本文文書へ分け、実symbolから関係を記録する。

基本ブロックはCFGのentry／exit、operations、branch value、successors、regionを保持する。条件の真偽、return／throw、finallyを通る遷移はRoslynの結果から表示する。gotoは実ラベルsymbolを、Spanやバッファのアクセスは束縛済み操作を使う。生成ASTとCFGで一意に対応しない箇所はUnknownの対応として残す。一般の変数の読書きを完全なdef-use解析として扱わず、最初はsymbolの参照情報と取得できたflow captureを記録する。制御フローの循環は別の配置で扱う。

段階間の最初の対応は元メソッド／実callsiteから実interceptor本文への対応とする。Fragmentと個々の生成命令の対応は、emit時の構造的な由来を最終ソースまで維持してから追加する。変数名やコメントの説明文から融合範囲を補完しない。本文は認可済みの明示取得へ接続し、JSON／HTMLの既定出力はマスクする。本文を含まない旧DLLは取得不能の状態を返す。文書とブロック／命令にはサイズ・件数上限と欠落診断を設ける。

最初の受入は、実際にforとifを出すWhere／Select／Sum、実際にgotoを出す早期終端、Spanを使用する経路の三つを生成・コンパイル・実行する。本文hashと各相対範囲、gotoの行先と戻り辺、補助型の束縛を照合する。同じ本文に異なる長さのPlan属性を付けても相対対応が保たれること、診断／上限／旧版／マスク時に取得不能や欠落を正しく表示することを確認する。

**三段階の最初の実装単位**

schema2の省略可能な`GeneratedCode`へ、最終本文とSHA256、本文相対UTF16範囲、基本ブロック、型解決済み操作、条件／通常遷移、領域の入退場とfinally経由を記録する。収集状態はAvailable／Unknown／Limitedとする。Roslynの合成操作に対応する本文位置がなければ、Start=-1・Length=0で範囲なしを示す。補助メソッドは呼出し先symbolまでを最初の範囲とし、本体の展開不足を診断で表示する。

通常の対象別取得と旧PlansはGeneratedCodeを省略する。`QueryPlanRequest.IncludeGeneratedCode=true`で既存のソース閲覧認可を通して明示取得する。既定の保存はGeneratedCode全体を除外し、コードを含める操作でのみ本文を保存する。省略可能な表示設定StructureLevelでRelational／Logical／Generatedを記録し、旧保存形式のハッシュを維持する。

本文65,536文字、基本ブロック2,048、操作8,192、制御辺8,192、領域2,048、診断128を初回の上限とする。既存の計画メタデータ2MiB上限も適用する。PE読取と資料読込では本文hash・範囲・識別子・接続先・領域の親子関係を検査し、循環した制御辺は許可する。これらの契約、生成経路、表示経路を実装中であり、合格範囲は実行結果の取得後に追記する。

最初のWindows Debug近接`cfg-debug-r1`は60件が成功した。実生成・コンパイル・実行するループ、gotoを含む本文、ReadOnlySpanの型解決、最終本文hash・相対範囲、型解決失敗と上限の明示、契約不正値、通常／明示API取得、OS所有者IPC、認証失効とマスキングを含む。生成器・管理・サーバーのビルドは警告／エラー0件。UIは前候補のDLLを用いた先行検証で、三段階UIの合格には含めない。証跡は`F:\Seamless\visualization-20261109-0e63c1c7\cfg-debug-r1-run`と`cfg-debug-r1/checks.trx`に保存した。

式は生成器の型解決済み情報から、演算、入力、型、NULL許容、ソース範囲、最適化前後、共有、短絡、融合を記録する。`a*b==c`はMultiplyとEqualの依存として表示できる確認例にする。定数畳み込み前後と、実行時に独立した評価があるかを区別する。

中間関係は列・型、順序、一意性、分割、保持、再利用を折り畳んで表示する。性質としての順序と実際のSort、表示用の関係ノードと実演算を区別する。独立計測できない式は融合先と測定範囲を示す。

### 5. 推定・実測・アクセス履歴

推定値は既存の統計・コスト所有元から取得する。単位、モデル、自己／包含、集計範囲、採取時点を付ける。根拠がある静的な件数は利用できるが、計画を表示するためにDBや副作用のある問い合わせを列挙しない。未対応の評価コストを定数で埋めない。

実測はクエリ全体の経過時間・初回出力・出力件数から接続し、バッチ・演算子の境界へ広げる。CPU、自己／包含、待機、回数、メモリ、I/Oは取得経路と範囲を検証したものから表示する。並列区間の時間を単純加算しない。

統計値は取得済み、推定、サンプリング、未収集、未対応、適用外、部分実行を区別する。欠落とゼロも区別する。実測の取得は明示操作とし、既存の実行認可・取消・取引・副作用の制約へ接続する。

計測は無効、軽量、詳細を設け、バッファ容量と収集終了条件を資源管理へ接続する。行や算術演算ごとの時刻取得を既定にしない。記録と表示の時間／イベント方式は独立して設定する。実行中・失敗・取消・部分結果・欠落を状態として扱う。

テーブルのアクセス履歴は既存監査を再利用する。ObjectIdでの厳密な絞り込みと、複数テーブルを参照する実行の対応が足りない箇所だけ、実行IDと対象テーブルの観測を追加する。クエリ本文の文字列検索を、正確なテーブルアクセスの証明に使わない。集計しかない期間は集計として表示する。スキーマ変更履歴と実データへのアクセスを区分する。

### 6. 共通の操作と視覚文法

| 要素 | 意味 |
|---|---|
