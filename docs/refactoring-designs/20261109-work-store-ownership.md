# 作業Storeの公開入口と所有

## 背景と引き継ぐ仕様

中間仕様書で確定した`db.CreateWorkStore()`と`work.CreateTsavorite<TKey,TValue>()`を通常のランタイムへ接続する。作業Storeと操作オブジェクトをusingで解放し、DB終了時も残存する作業Storeを回収する。名前文字列を利用者へ要求せず、汎用本体はランタイムで提供する。

## 現在の実装

Execution.Store.CreateTemporaryは子コレクション・予算・一時ディレクトリを所有する。ExecutionScopeには親予算、子資源の参照によるOwn・Release、終了時の回収がある。TsavoriteのStore拡張には名前付き生成があり、レイアウト・予算・デバイス・データ本体の登録を実装している。DatabaseContainerはExecutionScopeを所有し、終了時に破棄する。

## 接続する構造

ExecutionScope.CreateWorkStoreで既存の一時Storeを作る。未指定の上限は親予算から引き継ぎ、一時領域の配置先は親スコープを使う。作業Storeを親へ参照で登録し、明示Disposeでは登録を外す。親の終了との競合時も、生成に失敗したStoreの一時領域を回収する。Storeのロックを解放してから親へReleaseを通知する。

DatabaseContainer.CreateWorkStoreはDBの利用可能状態を確認して同じ入口を呼ぶ。DBと独立した検証ではExecutionScopeから作る。

Tsavoriteの辞書・集合の生成へ名前不要のオーバーロードを追加する。既存の名前付き生成と同じレイアウト・会計・操作オブジェクトを使う。一時Store内のファイル配置には衝突しない内部名を割り当てる。利用者の検索名として公開しない。再オープンに名前が必要な永続Storeは名前付き入口を使う。

## 検証と影響範囲

実データの読み書き、別コレクションの独立、親予算の合算・上限、明示Disposeと親終了時の解放、一時ディレクトリの回収、反復Dispose、生成失敗と並行終了を確認する。既存の名前付きStoreと保存復旧を回帰対象にする。DB側でも通常の公開入口から所有と予算を確認する。

この作業単位はW17のランタイム入口・所有・名前不要の生成へ対応する。Work名前空間からのContainer生成、型固定ストラテジの追加、残るキャンセル・障害・大規模・各環境の受入は担当の枝で接続する。

## 合意状態

利用者のW01〜W21の全残件実装指示と、作業Store方式・名前文字列不要・using寿命・親資源管理という確定済み仕様を引き継ぐ。公開入口と既存の資源管理を結ぶ内部構造の具体化である。

## 回収と作成の競合

新規の作業Store近接7件はDebugで成功した。既存のStore・ExecutionScopeを含む32件へ広げると、CreateTemporaryFileのowner.lock排他取得でIOExceptionを再現した。回収側はロックファイルの存在だけで取得を試み、作成側のOSファイル生成と排他確立の間へ入れる状態だった。

両作成経路ともowner.jsonは所有者ロック取得後に生成する。回収側は、そのファイルの存在を先に確認して作成途中の領域を除外する。内容の読み取りは従来どおり排他取得後に行い、破棄側のファイル共有を妨げない。待ち時間や再試行は追加しない。同じ3秒の既存並行試験とStore保存・復旧の回帰で確認する。

## 確認した範囲

Linuxで新規7件、既存Store・親スコープ・テーブル更新を加えたDebug・Release各46件が成功した。内訳はCore32件とDB14件で、実辞書・ハッシュ集合・キー付き集合の読み書き、共有予算の不足、明示解放・親終了時の回収、同時Dispose、失敗・取消時の作成を含む。既存の3秒競合試験は同じDLLで両構成各3回も成功した。

WindowsもDebug・Release各46件が成功した。標準のInvoke-Checks.ps1のExecution指定が削除済みcsprojを参照していたため、現在のTests/Seamless.Core.Testsへ接続した。追加したContains試験は公開メソッドの戻り値を直接検査し、列挙を行うAssert.Containsと区別した。新規試験の診断を修正した最終記述について、Linuxの作業Store6件も両構成で成功した。

LinuxのDB試験ビルドでは既存TableOperationTests.csの67行にxUnit2013の警告がある。作業Storeのライブラリ3層は警告・エラー0件だった。新規試験のWindows診断は解消後の候補で再確認した。

証跡はF:/Seamless/linux-desktop-recovery-20261109のwork-store-debug4、work-store-regression、work-store-regression2、work-store-race-repeatへ保存した。Windowsの正式入口の記録はF:/Seamless/work-store-windows-20261109に置く。生成Work、静的な更新方針の契約、途中の操作取消、実ディスク障害、強制終了と配布受入はW14・W15・W17で継続する。
