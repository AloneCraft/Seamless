# 同じ所属・分類内の現在画面の表示順

## 適用範囲

2026年11月10日に承認された最小単位として、テーブル・ビュー・関数を、同じDB・所属・分類内で並べ替える。関数の分類にはDBメンバーと登録関数を含む。操作ハンドルからのドラッグと、既存の対象メニューの上へ／下へ移動・既定順へ戻すを同じ表示順へ接続する。メニューは従来どおりShift+F10とキーボードで操作できる。

これは現在の画面内の表示順である。サーバーの移動・編集・保存APIは呼ばず、DBスキーマ、行データ、生成コード、列の物理順は変更しない。DBの表示順に使う既存のブラウザー保存Format1〜5も変更しない。

## 同一性と寿命

表示順はDBごとのツリー状態へ保持し、その中で所属と分類を区別する。異なるDB・所属・分類の同名対象へ順序を適用しない。処理時点で存在しない対象や、画面の定義／カタログ世代が変わる前のドラッグ要求を採用しない。名前変更・削除再作成・別版への同一性は推定しない。

現在のObjectIdは名前由来であり、関数の分類には別の定義版・成果物を持つ登録関数もある。今回の順序は再読み込みや定義変更で戻り、永続復元は未対応と画面・メニューに明示する。自己申告のStableIdだけを永続化の根拠へ追加しない。永続復元には対象ごとの版・成果物と同一性を確定する後続の契約が必要である。

## 操作と保護

ドラッグは既存の操作ハンドルを使用し、別の常設ボタンを増やさない。分類やスキーマをまたぐdropは受け付けず、許可された移動先に挿入位置を示す。Escapeとdragendで表示を解除する。ドラッグ終了による操作ハンドルのclick誤発火を抑止し、通常のクリックによるメニュー表示は維持する。

登録するJSイベントはワークスペースルートへの一組だけとし、個々の行へのリスナー登録を避ける。Tab・右クリック・既存のツリー操作と、DB・文書タブのドラッグはそれぞれの対象属性で区別する。View認可が失われた場合や対話準備前は表示順操作を受け付けない。行と展開した列一覧を一つのkey付き表示単位にして、並べ替えで編集中の入力を別対象へ付け替えない。

## 検証条件

同じ分類の上下／drop、関数の各戻り値種類と登録関数の混在、別DB・別所属・別分類・削除済み対象の拒否、再読み込みとカタログ変更による順序破棄、古いドラッグ世代の拒否、認可失効、未保存入力・選択・展開状態保持を確認する。近接試験後の実ブラウザー確認は、専用TMPDIRとIPC endpointの非衝突を確認した新しい隔離fixtureで行う。

## 現在の確認範囲

独立したheadless EdgeのDOM fixtureでは、実mouseによるnative drag、挿入位置表示、DOM順序、通常クリックとdrag後のメニュークリック、別group拒否、Escape取消、権限喪失、削除済みsource、Dispose時の状態解除を7条件で確認した。fixtureにはサーバー・DB・IPCがなく、実Manager受入とは分ける。
