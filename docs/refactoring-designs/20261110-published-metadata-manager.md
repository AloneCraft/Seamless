# 公開メタデータによるManager閲覧

## 背景と現状

現在の文書表示はGetDefinitionと個人下書きに依存する。GetDefinitionはViewとEditを要求する。CatalogのSchemas・Objects・ObjectDetailsはViewで公開メタデータを返し、Editがない利用者にはソース位置を除外している。行の取得にはViewとReadRows、ビューの実行にはView・ReadRows・Executeが必要である。

## 引き継ぐ仕様

編集利用者の下書き・検証・明示適用を維持する。公開版・成果物・対象IDを一致させる。ブラウザー状態は認証主体と実インスタンスを区別し、同一originで保存する。入力内容と実行結果を保存対象から除く。

## 合意した実装

- SchemasとObjectDetailsを共通管理APIと既存アダプターへ接続する。
- Editを持たない利用者は公開カタログから文書を構成する。編集用Definitionの取得と公開メタデータの取得を分ける。
- 公開カタログの空スキーマ名はDB直下への所属を表す。ツリーの名前付きスキーマ枝には含めず、DB直下のオブジェクトを一度だけ表示する。名前付きスキーマはオブジェクトが空でも保持する。
- データの画面と通信は既存の結果グリッド・関数データを共用する。読取専用の結果グリッドでは変更操作を抑止する。
- 行取得とビュー実行はサーバーの実行前・返却前にも現利用者の権限を再確認する。
- 公開メタデータ文書には公開版と成果物に基づく参照を保存する。ソース定義ハッシュを捏造しない。旧形式4の意味を維持して新形式へ拡張する。
- 復元対象のメタデータ取得後に、操作・未保存状態・権限を検査してから表示とタブを確定する。復元自身の表示変更で操作競合を発生させず、取得待機中の利用者の操作を上書きしない。
