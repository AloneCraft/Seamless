## 受け入れている制約（Q-03 の回答待ち）

| 制約 | 理由 | 解除の条件 |
|---|---|---|
| 並列区間の中では索引を拡張しない（`BeginParallel(見込み件数)` で回避） | Tsavorite の制約（EXP-0004。2.0.1-beta.5 と 2.1.8 で確認） | Tsavorite の修正 |
| 復元は一時的な LogSizeTracker を付けて行う（境界での保存と、メモリを縮めた開き直しの欠落を防ぐ）。復元後に衝突を検知したら例外 | Garnet 2.0.1-beta.6 以降（2.1.8 でも確認）の復元が、LogSizeTracker が無いとページを追い出さず内容を失う退行（upstream PR #1892 で入った）。upstream に該当の報告は見つからなかった | Garnet の修正。カナリアのテストが失敗したら、追跡を外せるか同じ実験で確かめる |
| 古い保存への `Store.Load(token)` は、より新しい保存を無効にする(Tsavorite はログを切り詰め、Persisted はファイルを巻き戻す)。マニフェストには残り、読むと例外にならず黙って誤った状態になる | 復元が「その保存より新しいログ」を破壊する設計。`Load` した後に `Save()` せず開き直すと、マニフェストの最新(無効)へ戻る | `Load` で、より新しい保存をマニフェストから外す(仕様の判断が要る) |
| **【2026-09-30 対応】** Persisted の `Set`/`Dictionary` の `Compact()` を `CompactSave()` に改名し、書き換えのあと必ず保存する(共通ストアの子資源ならストア全体の `Save`、単独ならその集合の `Commit`)ようにした。以前は、`Save` の後に `Compact()` して、次の `Save` の前に閉じる(クラッシュを含む)と、開き直しで保存した状態へ戻せず、`InvalidDataException("The saved state does not match the list files.")` でそのストアが開けなくなった。残る制約: `CompactSave` の前の保存番号のうち、この集合の状態は使えなくなる(`Load(古い保存番号)` は不整合になる) | `Compact` が追記だけでなく保存済みの内容を壊すので、追記だけを前提にした `RollbackTo`(件数・データ長を戻すだけ)では戻せない | 採用: `CompactSave` の直後に自動で状態を確定する。ほかの案(コピーオンライト、`Save` 後の `Compact` の拒否)は採らなかった |
| **【2026-10-06 対応】** `Store.Load(token)` は、記録を変える前に、全子資源が読み込めるかを確かめる(BUG-0019)。詰め直しと全削除のあとの保存は前の保存を記録から外し、詰め直しによるログの切り捨てはマニフェストの確定まで保留する(BUG-0022、EXP-0005)。**【2026-10-06 対応】** 全削除(`Clear`)は新しい世代のログのファイルへ切り替え、古い世代は新しい保存の確定後に消す(BUG-0023)。残り: 全削除のあと保存せずに前の保存へ `Load` することはできない(開き直せば戻れる) | 世代を切り替えたデバイスを Tsavorite の復元で安全に戻せなかった | 世代の切り替えを戻せるようにする |
