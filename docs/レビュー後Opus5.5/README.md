## ID の体系

| 接頭辞 | 意味 | 定義している文書 |
|---|---|---|
| F- | 行うべき機能 | 01 |
| INV- | 変更後も成り立ち続けること | 02 |
| NG- | やってはいけないこと | 02 |
| G- | 未実装・改善すべき点（ギャップ） | 04 |
| BUG- / OBS- / EXP- | 作業記録（`Work/qa/state.json`）の不具合・観測・実験の番号をそのまま使う | 04 |
| AC- | 受け入れ条件 | 06 |
| Q- | 判断事項 | 07 |

ID は変えない。内容が変わったら同じ ID の記述を直し、廃止するときは「廃止」と書いて残す。

## 状態の表記

| 表記 | 意味 |
|---|---|
| **検証済み** | 現在のコード（`f905f118` 以降）で、テストか実測で確かめた |
| **実装あり** | コードにあることを確かめた。この文書群のために改めて動かしてはいない |
| **一部** | 機能の一部だけがある |
| **未実装** | 呼び出し口がない、または呼ぶと「未実装」の例外になる（スタブ） |
| **対象外** | 意図して扱わない境界。不具合とはしない |
| **記録** | 作業記録や過去の文書にあるが、今回は再現していない |
| **推測** | コードや観測からの推測。確度（高・中・低）を付ける |
| **人の確認待ち** | 画面操作や製品判断など、自動では確かめられない |

「テストがある」ことと「今のコードでテストが通った」ことは区別する。後者だけを検証済みと書く。
